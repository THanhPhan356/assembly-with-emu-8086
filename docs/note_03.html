8086 arithmetic and control flow

Follow a value from calculation to decision: carry and overflow, implicit arithmetic registers, bit operations, branches, loops and saved return addresses.

00 · Predict the value, flags and next instruction

An instruction can change more than its destination. Arithmetic produces flags; a comparison produces only flags; a branch consumes a condition; a call saves a way back. This chapter connects those effects so that you can trace a whole program rather than memorize isolated mnemonics.

Prerequisites: note 01 for binary, two’s complement and segment:offset addresses, and note 02 for operand widths, ADD, FLAGS and stacks. Examples use the original 8086/8088, real mode, and Intel/MASM destination, source syntax. A word is 16 bits; a suffix h marks hexadecimal. Unmarked source-code numbers such as 10 are decimal.

  • Calculate arithmetic results and distinguish carry, borrow and signed overflow.
  • Prepare the implicit inputs and read the outputs of multiplication and division.
  • Use masks, comparisons, rotations and shifts without assuming undefined flags.
  • Choose signed or unsigned branches and trace counted loops.
  • Explain the stack frames used by CALL, RET, INT and IRET.

01 · ADC carries a result into the next word

ADD destination,source computes a fixed-width sum. ADC destination,source also adds the incoming CF. Both update CF, OF, AF, SF, ZF and PF. A carry is an unsigned result too large for the destination; overflow is a signed result outside its representable range.

; Same initial inputs for each independent example
mov al, 8Dh
mov bl, 0AEh
clc
adc al, bl          ; 8Dh + AEh + 0 = 13Bh: AL=3Bh
; Start over, now with incoming carry set:
mov al, 8Dh
stc
adc al, bl          ; 8Dh + AEh + 1 = 13Ch: AL=3Ch
Incoming CFResultCFOFAFSFZFPF
03Bh111000
13Ch111001

Signed interpretation: 8Dh is −115 and AEh is −82. The mathematical sums −197 and −196 both fall below −128, so OF=1 in both rows. PF counts the ones in the low result byte: 3Bh has five, 3Ch has four.

Build a 32-bit addition from two 16-bit additions

; DX:AX = 0001:FFFFh, CX:BX = 0000:0001h
add ax, bx          ; AX=0000h, CF=1
adc dx, cx          ; DX=0002h, CF=0
; Result DX:AX = 0002:0000h

The low-word ADD establishes CF; the high-word ADC consumes it. Do not insert a flag-changing instruction between them unless you know it preserves CF. A MOV is safe. The final ZF describes the high-word ADC result, not whether all 32 result bits are zero.

Memory width still matters

With AL=87h and byte DS:[DI]=11h, ADD AL,[DI] gives AL=98h: CF=0, OF=0, AF=0, SF=1, ZF=0, PF=0. In contrast, ADD AX,[DI] reads two bytes. Specifying only the first byte does not determine its answer. Ordinary ADD/ADC/SUB do not accept segment-register operands or two memory operands.

02 · SUB reports borrow separately from signed overflow

SUB destination,source stores destination − source modulo 2ⁿ and updates the six status flags. For subtraction, CF=1 means an unsigned borrow: the original destination was below the source. It does not mean that the stored result is negative.

FlagHow to calculate it for SUB
CF1 if unsigned destination < source.
OF1 if the operands have different signs and the result sign differs from the original destination sign.
AF1 if subtracting the low nibble needs a borrow from bit 4.
SF / ZFResult sign bit / whether the entire fixed-width result is zero.
PF1 if the low eight result bits contain an even number of ones.

Why a positive result can indicate signed overflow

In the last row, unsigned 135−17=118 fits, so CF=0. Signed 87h means −121; −121−17=−138 does not fit in an 8-bit signed value. The stored 76h is +118, so OF=1 even though SF=0. A carry from an internal two’s-complement addition is not the SUB borrow flag.

For multiword subtraction, the corresponding carry-consuming instruction is SBB destination,source: it subtracts the source and incoming CF. This follows the same low-word-first pattern as ADD/ADC.

Arithmetic and flag calculator

Enter hexadecimal operands without a sign. CF input is used only by ADC. CMP computes the subtraction flags while leaving the real operands unchanged.

ADC 8Dh,AEh with incoming CF=1 → 3Ch; CF=1, OF=1, AF=1, SF=0, ZF=0, PF=1.

03 · MUL and IMUL have implicit inputs and outputs

The original 8086 forms take one explicit register or memory source. The accumulator supplies the other operand, and the product occupies twice its width. An immediate source and the later two/three-operand IMUL forms are outside the original 8086 instruction set.

InstructionInput multiplicationOutputCF and OF
MUL r/m8Unsigned AL × source byteAXBoth 1 if AH ≠ 0; otherwise both 0.
MUL r/m16Unsigned AX × source wordDX:AXBoth 1 if DX ≠ 0; otherwise both 0.
IMUL r/m8Signed AL × signed source byteAXBoth 0 if AX is the sign extension of AL; otherwise both 1.
IMUL r/m16Signed AX × signed source wordDX:AXBoth 0 if DX is the sign extension of AX; otherwise both 1.
mov al, 11h
mov bl, 23h
mul bl              ; 17 * 35 = 595 = 0253h
                    ; AX=0253h, CF=OF=1 because AH=02h

mov ax, 1122h
mov bx, 2132h
mul bx              ; DX:AX=0238:BAA4h, CF=OF=1

mov al, -2
mov bl, 3
imul bl             ; AX=FFFAh (-6), CF=OF=0

The last product has a nonzero high byte, yet it fits in signed AL: FFh is the sign extension of FAh. That is why IMUL cannot use the unsigned “high half is nonzero” test.

Undefined does not mean unchanged. After MUL or IMUL, SF, ZF, AF and PF are undefined. Do not branch on them. Test the actual result with CMP or TEST when you need a zero or sign condition.

04 · Prepare the full dividend before DIV or IDIV

DIV source performs unsigned division; IDIV source performs signed division. Each takes one byte or word register/memory divisor. The quotient must fit in the single-width quotient register, even though the dividend is double width.

Divisor widthFull dividendQuotientRemainder
8 bitsAXALAH
16 bitsDX:AXAXDX

Extend a single-width value deliberately

; Unsigned byte 17 / 35
mov al, 11h
xor ah, ah          ; AX=0011h, not an unknown old AH:AL
mov bl, 23h
div bl              ; AL=00h, AH=11h (remainder 17)

; Unsigned word 1000 / 30
mov ax, 1000
xor dx, dx          ; DX:AX = 0000:03E8h
mov bx, 30
div bx              ; AX=33, DX=10 (decimal)

; Signed word -17 / 5
mov ax, -17
cwd                 ; sign-extend AX into DX:AX = FFFF:FFEFh
mov bx, 5
idiv bx             ; AX=-3 (FFFDh), DX=-2 (FFFEh)

Use CBW to sign-extend AL into AX before byte IDIV; use CWD to sign-extend AX into DX:AX before word IDIV. Neither changes FLAGS. Clearing AH or DX is suitable for extending an unsigned value; it would corrupt a negative signed dividend. If you already have a meaningful double-width dividend, keep its high half.

IDIV truncates the quotient toward zero. Its remainder has the dividend’s sign when nonzero, and dividend = quotient × divisor + remainder. Here −17=(−3)×5+(−2).

Recognize divide errors before running

  • A zero divisor causes a type-0 divide-error interrupt.
  • A quotient that does not fit also causes a divide error: AX=1000h divided by an 8-bit divisor of 1 would require AL=1000h.
  • For unsigned word division by nonzero BX, DX < BX is the condition that the quotient fits in AX. Clearing DX establishes it for a single unsigned word.

After DIV and IDIV, all six status flags (CF, OF, AF, SF, ZF, PF) are undefined. The slide’s broad “does not affect flags” wording must not be treated as a preservation guarantee. Use the quotient/remainder or a fresh comparison.

05 · INC, DEC, NOT and NEG have different flag contracts

InstructionResultFlag behavior
INC destinationdestination + 1Updates OF, AF, SF, ZF, PF; preserves CF.
DEC destinationdestination − 1Updates OF, AF, SF, ZF, PF; preserves CF.
NOT destinationInvert every operand bitPreserves all flags.
NEG destination0 − destination, modulo the widthUpdates all six status flags as subtraction.

INC is not interchangeable with ADD 1 when a later instruction depends on CF. Likewise DEC is not a complete substitute for SUB 1. Both can overflow: INC 7Fh gives 80h with OF=1; DEC 80h gives 7Fh with OF=1.

stc
mov al, 7Fh
inc al              ; AL=80h, OF=1, CF still 1
mov al, 0
dec al              ; AL=FFh, CF still 1 (preserved)

mov ax, 0A23Ch
not ax              ; AX=5DC3h, all flags unchanged
; Independently, start again from A23Ch:
mov ax, 0A23Ch
neg ax              ; AX=5DC4h: invert then add 1

00h00h000Zero needs no borrow.

For NEG, CF=1 exactly when the input is nonzero. AF depends on the low nibble, rather than always becoming 1. OF=1 only for the most negative signed input (80h or 8000h). These edge cases matter when checking a general statement against one classroom example.

For AND, OR and XOR: CF=0, OF=0, and SF/ZF/PF describe the result. AF is undefined. In particular, XOR AL,AL gives ZF=1, SF=0, PF=1, CF=OF=0; it does not promise AF=0. NOT has a different contract and leaves all flags unchanged.

For a field in bits 4–6, first isolate it with AND AL,70h, then shift right four times using CL=4. Isolating a field and moving it into the low bits are separate operations.

07 · CMP and TEST ask questions without storing a result

CMP A,B computes the same six status flags as SUB A,B, but leaves A and B unchanged. TEST A,mask computes the same flags as AND, without storing the AND result. A following conditional branch reads those flags.

test al, 01h
jz even_value       ; low bit is clear: unsigned or signed integer is even
; A nonzero low bit falls through.

test al, 0Ch        ; mask bits 2 and 3
jz neither_set      ; both selected bits are clear
; Otherwise at least one is set, not necessarily both.

To require both selected bits, copy AL into a temporary register, AND that copy with 0Ch, and compare the copy with 0Ch. TEST only tells you whether the masked result is zero; it does not implement a general “all selected bits set” test.

The same comparison has signed and unsigned interpretations

mov al, 80h
cmp al, 01h         ; internal result 7Fh, AL remains 80h
; CF=0, ZF=0, SF=0, OF=1
; unsigned: 128 > 1, so JA is true
; signed:  -128 < 1, so JL is true

SF alone cannot decide signed less-than after CMP: the subtraction may have overflowed. Signed less-than uses SF ≠ OF. Unsigned less-than uses CF=1. Equality uses ZF in either interpretation. Keep CMP adjacent to the branch or account for any intervening flag changes.

A simpler lecture comparison, CMP AX,BX with AX=1123h and BX=0054h, internally computes 10CFh: CF=0, OF=0, AF=1, SF=0, ZF=0, PF=1. AX and BX retain their input values.

08 · Set only the control flag you intend to change

InstructionEffectTypical use
CLC / STC / CMCCF=0 / CF=1 / invert CFInitialize ADC/SBB or carry rotations.
CLD / STDDF=0 / DF=1String indices move forward / backward.
CLI / STIIF=0 / IF=1Disable / enable maskable external interrupts.

These instructions preserve the other flags. IF does not disable NMI or an explicitly executed software INT. On the original 8086, STI defers recognition of maskable external interrupts until after the following instruction. Avoid using CLI/STI in ordinary DOS practice programs unless you understand the environment and restore the intended state.

Choose CLC before RCL when the carry bit should enter as zero. Choose CLD before a forward string copy. These initial conditions are part of the algorithm, rather than incidental leftovers from earlier instructions.

09 · Rotate a ring of bits, with or without CF

A rotation wraps outgoing bits around. ROL/ROR rotate the operand itself and also copy the outgoing bit into CF. RCL/RCR include CF as an extra position in the ring: nine positions for a byte, seventeen for a word.

One-bit instructionBit shifted into operandNew CFAL from 4Dh, incoming CF=1

ROR AL,1Old bit 0 → bit 7Old bit 0A6h, CF=1, OF=1
RCL AL,1Old CF → bit 0Old bit 79Bh, CF=0, OF=1
RCR AL,1Old CF → bit 7Old bit 0A6h, CF=1, OF=1

On the original 8086, the count operand is 1 or CL. A literal count such as RCL AX,4 is not a native 8086 encoding; an assembler might expand it or target a later processor. The examples here use CL explicitly.

Rotations preserve SF, ZF, AF and PF. For a count of 1, left-rotation OF is the XOR of the new MSB and CF; right-rotation OF is the XOR of the two highest result bits. For a multibit rotation, OF is undefined. A trace of four single-step rotations explains the bit movement, but it does not make the final OF defined for one instruction with CL=4.

10 · Shift for scaling, but account for lost bits

SHL/SAL inserts zero on the right. SHR inserts zero on the left. SAR copies the original sign bit into the leftmost position. CF receives the last bit shifted out.

Instruction, count 1InterpretationOF
SHL / SALMultiply by 2 modulo the operand width; inspect CF/OF for lost unsigned/signed range.New MSB XOR CF.
SHRUnsigned division by 2, discarding remainder into CF.Original MSB.
SARSigned division by 2 with rounding toward negative infinity.0.

For these shifts with a nonzero count, SF, ZF and PF describe the final result; AF is undefined. OF is defined only for count 1, and undefined for larger counts. A zero count leaves the operand and flags unchanged. The trace tool uses 1–16 so every listed step moves a bit.

SAR and IDIV round differently for negative odd values: −3 shifted right once by SAR becomes −2; −3 divided by 2 with IDIV becomes −1 with remainder −1. Replacing signed division with a shift can change the answer.

Bit movement tracer

Input is hexadecimal; count is decimal. Each row shows the state after one conceptual bit movement. For a multibit instruction, the summary correctly leaves OF undefined.

RCL 3D2Eh by 4 → D2E1h, CF=1. OF is undefined; SF/ZF/AF/PF are unchanged.

11 · JMP changes where execution continues

FormChangesHow its destination is supplied
Short relativeIP onlyEB disp8: signed −128…+127 bytes from next IP.
Near relativeIP onlyE9 disp16: relative 16-bit offset from next IP, modulo 10000h.
Near indirectIP onlyA register or memory word supplies the new IP.
Far directCS and IPEA followed by immediate offset word and segment word.
Far indirectCS and IPA four-byte memory pointer supplies offset then segment.

Encode a backward short jump

A two-byte JMP begins at IP=0100h; the target label is 00F8h. The next IP is 0102h. Thus displacement=00F8h−0102h=−10=F6h as a signed byte. The bytes are EB F6. Calculating from 0100h would land two bytes too late.

For JMP A000h:BCDEh, the direct far bytes are EA DE BC 00 A0. A near JMP BX sets IP=BX; it does not read memory. A far indirect jump such as JMP DWORD PTR [BX] reads the offset word and segment word from memory at DS:BX.

JMP does not save a return address and does not change FLAGS. Use a CALL when execution should later return. For ordinary labels, let the assembler resolve displacement and check range.

12 · Match a branch to the meaning of the comparison

Conditional jumps read existing flags and leave them unchanged. On the original 8086, their direct destination is a signed short displacement. A branch outside that range needs a different layout, often an inverted short condition around a near JMP.

Keep the condition alive until the branch

cmp ax, bx
mov dl, 0           ; MOV preserves the comparison flags
jbe not_above       ; unsigned AX <= BX
mov dl, 1

; DL is 1 exactly when unsigned AX > BX.

If you inserted ADD, TEST or a shift before JBE, that branch would read a different condition. An INC also changes ZF/SF/OF even though it preserves CF. Know which particular flags the branch needs.

JCXZ label is useful for loops, but differs from these flag branches: it tests CX directly and does not inspect or change FLAGS.

13 · LOOP counts with CX without rewriting FLAGS

LOOP first decrements CX modulo 65536, then jumps if CX is not zero. Unlike an actual DEC instruction, LOOP does not update FLAGS. LOOPE/LOOPZ and LOOPNE/LOOPNZ add a test of the existing ZF.

InstructionBranch condition after decrementing CX
LOOP labelCX ≠ 0
LOOPE / LOOPZ labelCX ≠ 0 and ZF=1
LOOPNE / LOOPNZ labelCX ≠ 0 and ZF=0

A zero count needs a guard before the body

; CX contains the requested number of iterations.
jcxz finished       ; skip the body when the request is zero
again:
    ; Body: preserve CX, and supply ZF here if using LOOPE/LOOPNE.
    loop again
finished:

If execution enters a LOOP body with CX=0 and no guard, the first LOOP wraps CX to FFFFh and branches. If nothing else changes CX, the body runs 65536 times before termination. A LOOP instruction tests after decrementing, so “CX is zero at entry” is not a zero-iteration guarantee.

The three source panels start with MOV CX,16, meaning decimal 16. In the middle panel, CMP AL,10 produces ZF=0 after AL first becomes 1, so LOOPE exits with CX=15. The right panel instead repeats while AL is not 10 and exits with CX=6. Read the condition, rather than the visual similarity of the code.

14 · CALL saves a return address; RET must match it

A CALL transfers control after saving the address of the following instruction on SS:SP. A near CALL saves the return IP (two bytes). A far CALL saves the old CS and return IP (four bytes), with IP at the new top. Neither changes FLAGS merely by calling.

TransferEntry stack effectMatching return
Near CALLSP−2; store next IPRET pops IP; CS stays unchanged.
Far CALLPush old CS, then next IP; total SP−4RETF pops IP, then CS.

Trace the far call from the slides

The instruction begins at CS:IP=1000h:2345h (physical 12345h). A five-byte direct far CALL to A000h:BCDEh saves next IP=234Ah and transfers to physical ABCDEh. With SS=F000h and SP=ABC4h, the saved frame is:

Physical addressByteMeaning
FABC0h4AhReturn IP low; SP points here.
FABC1h23hReturn IP high.
FABC2h00hOld CS low.
FABC3h10hOld CS high.

RETF restores CS:IP=1000h:234Ah and SP=ABC4h. A plain near RET would pop only the IP and leave two bytes behind, with the wrong CS still active. Some assemblers select a far return from a FAR procedure declaration; when describing machine behavior, distinguish near RET from RETF explicitly.

Define the routine’s register agreement

A return address is not automatic preservation of AX, BX or FLAGS. Decide which registers hold inputs, which return outputs, and which the callee promises to restore. Balance temporary PUSH/POP pairs before returning. A near helper in the practice section intentionally returns its sum in AX.

15 · INT and IRET save and restore FLAGS as well

In the original real-mode system, the interrupt vector table occupies physical addresses 00000h–003FFh: 256 entries of four bytes. Vector n is at physical 4 × n, equivalently 0000:(4 × n), with an offset word followed by a segment word.

Step for software INT nEffect
1Push FLAGS, saving the caller’s original flag state.
2Clear IF and TF, then push the old CS and next IP.
3Load the handler IP and CS from vector n. The top of the stack is the saved IP.
IRETPop IP, CS and FLAGS, in that order; six saved bytes are consumed.

For INT 21h, the vector begins at 4×21h=0084h; its four bytes are at physical 00084h–00087h. This lookup is fixed at the low-memory vector table, regardless of DS. It does not mean that every interrupt changes DS to zero.

A software INT remains executable with IF=0. IF controls maskable external interrupt recognition, rather than explicit INT instructions or NMI. IRET restores FLAGS, so it is not interchangeable with RETF. An external interrupt’s saved IP identifies where execution resumes; it need not follow a two-byte software INT.

Scope: this explains the frame and vector lookup. Do not overwrite DOS vectors or try to validate hardware interrupt timing from the practice programs. Protected-mode interrupt descriptors belong to a later chapter.

17 · Five complete programs to step through

Create a separate COM program for each listing in emu8086. Stop at the checkpoints before the final top-level RET. These listings use the COM template’s initialized stack and return convention; they are not boot sectors. Observe registers and only the flags the instruction defines.

A · Add two 32-bit unsigned values

org 100h
mov ax, 0FFFFh
mov dx, 0001h
mov bx, 0001h
mov cx, 0000h
add ax, bx
adc dx, cx
; Checkpoint: DX:AX=0002:0000h, CF=0
ret

The low word overflows into CF, then ADC adds that carry to the high word. Final ZF describes DX only.

B · Read the implicit multiply and divide registers

org 100h
mov al, 11h
mov bl, 23h
mul bl
; Checkpoint 1: AX=0253h, CF=OF=1
div bl
; Checkpoint 2: AL=11h, AH=00h; flags undefined
mov ax, -17
cwd
mov bx, 5
idiv bx
; Checkpoint 3: AX=FFFDh (-3), DX=FFFEh (-2)
ret

DIV uses the entire product AX, so it needs no clearing of AH here. CWD prepares the later negative dividend.

C · Compare the same byte two ways

org 100h
mov al, 80h
mov dl, 0
mov dh, 0
cmp al, 1
jl signed_less
jmp unsigned_check
signed_less:
mov dl, 1
unsigned_check:
cmp al, 1
ja unsigned_above
jmp finished
unsigned_above:
mov dh, 1
finished:
; Checkpoint: AL=80h, DL=1, DH=1
ret

DL reports signed −128<1; DH reports unsigned 128>1. CMP never overwrites AL.

D · Contrast carry rotation and right shifts

org 100h
mov ax, 3D2Eh
clc
mov cl, 4
rcl ax, cl
mov bx, ax
; Checkpoint 1: BX=D2E1h, CF=1, OF undefined
mov al, 0A6h
sar al, 1
mov dl, al
mov al, 0A6h
shr al, 1
mov dh, al
; Checkpoint 2: BX=D2E1h, DL=D3h, DH=53h
ret

The full RCL output is saved before AL is reused. SAR and SHR start from the same original byte.

E · Sum 1 through 10 using a near helper

org 100h
xor ax, ax
mov bx, 1
mov cx, 10
again:
call add_term
inc bx
loop again
; Checkpoint: AX=0037h (55), BX=000Bh, CX=0
; SP equals its value before the first CALL.
ret
add_term:
add ax, bx
ret

The helper returns its updated accumulator in AX and preserves BX/CX. LOOP uses CX without disturbing the helper’s flags; INC BX changes some flags, which this loop does not inspect.

Expected results and control flow were checked in a separate 16-bit assembler/emulator. This does not verify original processor timing, undefined flag values, or the emu8086 interface. The listings have not been stepped through in the emu8086 application.

18 · Worked revision exercises

Predict the state before revealing the answer. A complete answer states the operand width and separates a defined flag from an undefined or preserved one.

01 · Carry is an input

AL=8Dh, BL=AEh and CF=1. Execute ADC AL,BL. Give the result and six flags.

Show worked answer

The raw sum is 13Ch; AL=3Ch. CF=1, OF=1, AF=1, SF=0, ZF=0, PF=1. Both signed inputs are negative and their mathematical sum is below −128.

02 · A multiword zero test

ADD AX,BX gives AX=0001h, CF=0. ADC DX,CX then gives DX=0000h, ZF=1. Is the whole result zero?

Show worked answer

No. DX:AX=0000:0001h is nonzero. ZF belongs to the last instruction’s 16-bit result. To test the whole value, OR the halves in a temporary register and inspect ZF.

03 · Borrow and overflow diverge

Predict SUB AL,11h from AL=87h.

Show worked answer

AL=76h, CF=0, OF=1, AF=0, SF=0, ZF=0, PF=0. Unsigned 135−17 fits; signed −121−17 does not.

04 · Read the product halves

AX=1122h and BX=2132h before MUL BX. Which registers hold the product?

Show worked answer

The product is 0238BAA4h, so DX=0238h and AX=BAA4h. CF=OF=1. SF/ZF/AF/PF are undefined.

05 · Prepare signed division

Divide a signed word −17 by BX=5. Why is XOR DX,DX wrong?

Show worked answer

Use MOV AX,-17; CWD; IDIV BX. The sign-extended dividend is FFFF:FFEFh, producing AX=FFFDh and DX=FFFEh. Clearing DX would instead supply a large positive dividend.

06 · A quotient can overflow

AX=1000h and BL=01h before DIV BL. Is a nonzero divisor enough?

Show worked answer

No. Quotient 1000h cannot fit in AL, so a type-0 divide error occurs. Byte division has an 8-bit quotient, not a 16-bit quotient.

07 · Preserved CF is not zero CF

CF=1 and AL=00h. What happens after DEC AL?

Show worked answer

AL=FFh; CF remains 1. OF=0, AF=1, SF=1, ZF=0, PF=1. DEC preserves the old CF rather than calculating a borrow flag.

08 · NEG edge cases

Give CF, OF and AF after negating byte values 00h,10h and 80h.

Show worked answer

00h→00h: CF0 OF0 AF0. 10h→F0h: CF1 OF0 AF0. 80h→80h: CF1 OF1 AF0. Neither CF nor AF is unconditionally set.

09 · Check a mask precisely

AL=04h. Does TEST AL,0Ch establish that bits 2 and 3 are both set?

Show worked answer

No. ZF=0 says at least one selected bit is set; bit 3 is clear. AL remains 04h. Compare a masked copy with 0Ch to require both bits.

10 · Choose the comparison interpretation

After CMP AL,01h with AL=80h, which of JA, JL and JS are taken?

Show worked answer

JA and JL are true; JS is false. The internal result 7Fh gives CF0 ZF0 SF0 OF1. Unsigned 128>1, signed −128<1, and the result sign bit is zero.

11 · A multibit rotation

AX=3D2Eh, CF=0, CL=4. After RCL AX,CL, give AX, CF and OF.

Show worked answer

AX=D2E1h and CF=1. OF is undefined because the count is greater than 1. SF/ZF/AF/PF retain their original values.

12 · Rounding matters

Compare SAR on signed −3 by one bit with IDIV by signed 2.

Show worked answer

SAR gives −2 (round down); IDIV gives quotient −1 and remainder −1 (truncate toward zero). Both are valid but different operations.

13 · Calculate a relative displacement

A short JMP starts at 0100h and targets 00F8h. Give its bytes.

Show worked answer

Next IP=0102h. Displacement=−10, encoded F6h. The instruction is EB F6.

14 · Zero-count trap

A loop body starts with CX=0, changes no CX itself and ends with LOOP back to the body. How many body executions occur?

Show worked answer

65536. The first LOOP decrements 0 to FFFFh. Put JCXZ before the body to make an initial zero count skip all work.

15 · Return from a far call

SS=F000h and initial SP=ABC4h. A far CALL saves return CS:IP=1000h:234Ah. Give the new top and the matching return.

Show worked answer

SP=ABC0h, physical top FABC0h. Bytes in ascending addresses are 4A 23 00 10. RETF restores IP then CS and returns SP to ABC4h.

16 · Find the interrupt vector

Where is the INT 21h vector, and why is RETF not sufficient to return from its handler?

Show worked answer

The vector’s offset word is at physical 00084h, segment word at 00086h. INT also saves FLAGS; IRET restores IP, CS and FLAGS. RETF would leave saved FLAGS on the stack and fail to restore them.

Answer key for offline revision and printing

1. B. SUB sets CF for an unsigned borrow, independently of signed interpretation.

2. A. INC updates OF/AF/SF/ZF/PF while preserving the old CF.

3. C. Byte division uses AX as dividend, AL as quotient and AH as remainder.

4. B. CWD fills DX with the sign extension of AX without changing FLAGS.

5. B. AND clears CF/OF, derives SF/ZF/PF from the result and leaves AF undefined.

6. C. Signed comparison corrects for subtraction overflow by testing SF XOR OF.

7. B. The count is 1 or CL; later processors add immediate-count encodings.

8. A. SAR preserves the sign and rounds toward negative infinity; IDIV truncates toward zero.

9. A. The processor adds the displacement after consuming the instruction bytes.

10. B. LOOP updates CX but preserves FLAGS, including ZF.

11. C. RETF pops IP and CS; a far call does not save FLAGS.

12. B. IF controls maskable external interrupts, not explicit software INT or NMI.

Corrections that affect your programs

  • ADC 8Dh+AEh has OF=1 with either incoming carry. The two inputs are negative signed bytes and their sum does not fit.
  • SUB CF is unsigned borrow. Signed less-than after CMP uses SF≠OF, rather than SF alone.
  • MUL/IMUL permit register or memory sources. Their undefined status flags, and all six flags after DIV/IDIV, must not be assumed unchanged.
  • A byte DIV needs the whole AX. A lecture example naming only AL leaves the dividend incomplete; the example here explicitly initializes AH.
  • NEG does not always set CF/AF: zero input clears CF, and a zero low nibble clears AF.
  • Multibit shifts and rotations leave OF undefined even when a one-bit-at-a-time drawing suggests a final value.
  • The slide’s three loop panels stop under different conditions; LOOPE is not a loop that keeps incrementing until equality is first reached.
