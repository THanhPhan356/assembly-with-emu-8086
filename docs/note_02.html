8086 data transfer: instruction encoding, pointers and stacks

Learn to predict what an instruction changes: its bytes, operands, addresses and saved state. Original slide illustrations sit beside worked examples, practical programs and revision questions.

Scope: session 2, part 1 · Intel 8088/8086 · real mode · Intel/MASM syntax · emu8086.

00 · Learning objectives and prerequisites

An instruction must answer three questions: which value, where, and how many bytes? This chapter develops that habit through machine-code examples, pointer operations and byte-by-byte stack traces.

Before starting, review segment:offset addressing, little-endian words and 8086 address forms in note 01. All unqualified memory operands below use DS unless the address contains BP, which normally selects SS.

  • Encode register/memory MOV instructions and explain the special [BP] case.
  • Distinguish copying data, calculating an offset and loading a far pointer.
  • Trace PUSH, POP and preservation of registers and flags.
  • Identify the implicit registers in IN, OUT and XLAT.

Notation: Intel/MASM syntax uses destination, source. A suffix h denotes hexadecimal. [address] means memory at that address, EA means effective offset, and a word is 16 bits. BYTE PTR and WORD PTR specify memory operand width.

01 · MOV copies a value of a known width

MOV destination, source replaces the destination with the source value. The source keeps its value. MOV does not change FLAGS.

mov ax, bx                 ; AX receives BX
mov ah, 'A'                ; AH = 41h, the ASCII code for A
mov al, [1234h]            ; one byte from DS:1234h
mov word ptr [1234h], 5678h ; [1234h]=78h, [1235h]=56h

The size of a register determines the other operand's width. MOV [BX],AL stores one byte; MOV [BX],AX stores two. When an immediate and an untyped memory address leave the width ambiguous, state it explicitly.

DestinationLegal sourcesRestrictions
8-bit general register8-bit register, byte memory, 8-bit immediateNo segment register as the other operand.
16-bit general register16-bit register, word memory, immediate, segment registerAll operands must match the required width.
DS, ES or SS16-bit general register or word memoryNo immediate source and no segment-to-segment MOV.
Byte or word memorySame-width general register, immediate; segment register for a wordNo ordinary memory-to-memory MOV.

CS may be read as a source, for example MOV AX,CS, but cannot be a MOV destination. IP is not a general MOV operand. Changing CS:IP requires a control-transfer instruction.

Repair an invalid instruction by identifying the restriction

Invalid or ambiguousWhyOne valid replacement
MOV AH,1234hThe value does not fit into 8 bits.MOV AX,1234h, if a word was intended.
MOV [SI],[DI]Both operands are memory.MOV AL,[DI] then MOV [SI],AL for a byte copy.
MOV DS,1234hA segment register cannot take an immediate.MOV AX,1234h then MOV DS,AX.
MOV ES,DSSegment-to-segment MOV is unavailable.MOV AX,DS then MOV ES,AX.
MOV [BX],1No declared byte/word width.MOV BYTE PTR [BX],1 or MOV WORD PTR [BX],1.

When using a temporary register, account for its old value if the surrounding program still needs it. Also remember that MOV AX,DS copies the 16-bit segment value, rather than reading memory at DS.

02 · Read the MOV encoding one field at a time

For the register/memory MOV family, the first byte is 100010dw. The second byte is mod reg r/m, divided into 2, 3 and 3 bits. Additional displacement bytes follow when required.

FieldMeaning in this MOV family
d=1The register named by reg is the destination.
d=0The register named by reg is the source.
w=0 / w=1An 8-bit / 16-bit transfer.
mod=00Memory, no displacement, except r/m=110 means a direct 16-bit offset.
mod=01Memory plus a signed 8-bit displacement.
mod=10Memory plus a 16-bit displacement.
mod=11Both operands are registers; r/m is a register code.

8086 addressing permits a base BX or BP, an index SI or DI, and a displacement in the supported combinations above. It has no general [SP], [AX], [SI+DI] or scaled-index form.

The direct-address exception: mod=00, r/m=110 means [disp16], not [BP]. Encode plain [BP] using mod=01, r/m=110 and a zero displacement byte.

These bits describe one instruction family. MOV involving segment registers, immediates or the accumulator's direct-memory forms can use other opcodes. A general format diagram does not imply that every instruction contains every field.

03 · Build and check complete machine-code bytes

Use this sequence: identify operand width, choose d, encode mod/reg/r/m, then append displacement bytes in little-endian order. Count bytes only after identifying the instruction form.

Example A: MOV BP,SP

Choose d=1, w=1 and reg=BP=101. Both operands are registers, so mod=11 and r/m=SP=100.

100010 1 1 | 11 101 100
   8Bh     |    ECh
MOV BP,SP  -> 8B EC

89 E5 is another valid encoding of the same operation, using d=0 with the register roles reversed. The lecture's d=1 choice for a register-to-register example is a convention for that derivation.

Example B: MOV DL,[DI+1]

d=1, w=0 gives 8Ah. mod=01 chooses disp8; reg=DL=010 and r/m=DI=101 give 01 010 101, or 55h. Append 01h: 8A 55 01.

Example C: MOV BP,[DI+1000h]

d=1, w=1 gives 8Bh. mod=10, reg=101 and r/m=101 give ADh. The 16-bit displacement 1000h is stored 00h then 10h: 8B AD 00 10.

Example D: direct address versus plain BP

Instructionmod reg r/mBytesReason
MOV [1000h],DL00 010 11088 16 00 10Direct offset 1000h uses the special mod=00 form.
MOV [BP],DL01 010 11088 56 00An explicit zero disp8 distinguishes [BP] from a direct address.

Example E: why +0F3h is not a signed 8-bit displacement

The number of hexadecimal digits does not determine displacement size. Although F3h fits in one byte as an unsigned value, disp8 is signed. Its range is −128 to +127. F3h sign-extends to FFF3h, which represents −13.

Intended instructionCorrect bytesEffective offset
MOV [SI+0F3h],CL88 8C F3 00SI + 243, using disp16.
MOV [SI-0Dh],CL88 4C F3SI − 13, using disp8.

Correction to the lecture example around 25:00: using a single displacement byte F3h for the written positive offset +0F3h changes the address. With SI=1000h, the positive offset gives 10F3h; the signed byte F3h gives 0FF3h.

Inspect a displacement byte

Enter F3 to see why its signed meaning is −13.

Little-endian order also applies to immediate words, but an immediate value is data while a displacement contributes to the address. Effective offsets wrap to 16 bits after address arithmetic.

Lecture: 22:00–50:00. The positive-displacement correction is checked against Intel documentation and independently assembled byte sequences.

04 · XCHG swaps two values without a temporary register

XCHG exchanges two same-width general registers or one general register and one memory operand. It accepts no immediate, segment register or memory-to-memory pair. FLAGS is unchanged.

mov ax, 1234h
mov bx, 5678h
xchg ax, bx       ; AX=5678h, BX=1234h

A word exchange changes two memory bytes

Suppose AX=1234h and the bytes at DS:0200h and DS:0201h are 78h and 56h. After XCHG AX,[0200h], AX=5678h and those memory bytes are 34h and 12h. The instruction exchanges complete words.

If a register also contributes to the memory address, the address is determined from the register values used for that instruction. For example, XCHG DI,[BX] uses DS:BX and changes DI, leaving BX unchanged.

Lecture: 68:00–75:00. Source deck: Part2, slide 51.

05 · LEA calculates an offset without reading memory

LEA r16,memory-expression calculates the effective offset described by the memory expression and stores that 16-bit offset in a general register. It does not read the bytes at that address, add the segment base or change FLAGS.

mov bx, 1000h
mov di, 0020h
lea dx, [bx+di+4]   ; DX=1024h, no memory read
mov ax, [bx+di+4]   ; AX=the word stored at DS:1024h

Changing DS would change which physical memory location the MOV reads. It would not change the LEA result. An effective offset can still be useful when no initialized data exists at that address.

InstructionResult or restriction
LEA DI,[DI]DI receives its existing value. No memory is loaded.
LEA CX,[BP+SI+8]CX receives the low 16 bits of BP+SI+8. SS is not added.
LEA AL,[DI]Invalid: the destination must be a 16-bit general register.
LEA DS,[DI]Invalid: a segment register cannot be the destination.
LEA [BX],[DI]Invalid: the destination cannot be memory.

For a declared label, LEA DX,message and MOV DX,OFFSET message can obtain the same offset in MASM-style code. A bare label in a MOV may instead denote its contents, depending on declaration and assembler syntax. Use explicit syntax when learning.

Lecture: 75:00–83:00.

06 · LDS and LES load an offset and a segment from four bytes

LDS r16,m32 and LES r16,m32 read a four-byte far pointer from memory. The first word becomes the destination general register. The second word becomes DS for LDS, or ES for LES. FLAGS is unchanged.

Byte addressStored byteRole for LES DI,[0100h]
DS:0100h11hLow byte of the new DI.
DS:0101h22hHigh byte of the new DI.
DS:0102h33hLow byte of the new ES.
DS:0103h44hHigh byte of the new ES.

The result is DI=2211h, ES=4433h, giving a loaded pointer ES:DI=4433h:2211h. The pointer's storage address and the address it describes are different. Here the storage is DS:0100h; the loaded pointer describes physical address 46541h.

The source uses the original address values

Suppose DI=1111h and DS:[1111h..1114h] contains 11h,22h,33h,44h. LES DI,[DI] reads that entire pointer from the original DS:1111h, then leaves DI=2211h and ES=4433h. It does not relocate the second word to DS:2213h after DI changes. Likewise LDS reads its source using the old DS before loading a new DS.

Instruction, starting with DI=1111hMeaning
LEA DI,[DI]DI=1111h; memory and ES are untouched.
MOV DI,[DI]DI=2211h; ES is untouched.
LES DI,[DI]DI=2211h and ES=4433h.

The destination must be a 16-bit general register and the source must be memory holding four readable bytes. LES AL,[DI], LES ES,[DI] and LES BX,AX are invalid.

Lecture: 83:00–102:00. LDS is the corresponding DS-loading form; it is named in the slides and resumed after the break. The captions have a gap there.

07 · LAHF and SAHF access only five status flags

LAHF loads SF, ZF, AF, PF and CF into their corresponding positions in AH. SAHF copies those five AH bits back into FLAGS. Neither instruction has explicit operands.

AH bit76420
Status flagSFZFAFPFCF

SAHF does not restore OF, DF, IF or TF. Treat the other AH bit positions as reserved when using a saved flag image. A complete FLAGS save and restore requires PUSHF and POPF.

stc          ; CF=1
lahf         ; AH now contains a snapshot of five flags
clc          ; CF=0, AH is unchanged
sahf         ; CF becomes 1 again

This works only while AH keeps the snapshot. Writing AX or AH between LAHF and SAHF destroys the saved bits. The instructions support compatibility with earlier Intel programming models; they are actual 8086 instructions, rather than an instruction pair that can be assumed to exist unchanged on the 8085.

Lecture: 112:00–114:00. The five-bit restriction is checked against Intel’s instruction description. Some short emulator reference tables overstate SAHF’s effect on OF.

08 · PUSH and POP transfer words through SS:SP

The stack is memory addressed by SS:SP and used in last in, first out order. On the original 8086, ordinary PUSH and POP transfer one word. They do not change FLAGS.

PUSH: decrement, then store

SP ← (SP − 2) mod 10000h
word at SS:SP ← source

For a word value V, the byte at the new stack top receives V's low byte and the following byte receives its high byte.

InstructionSP after instructionBytes written, low address first
Initial state000AhAX=1234h, BX=7856h, SS=1300h.
PUSH AX0008h13008h=34h, 13009h=12h.
PUSH BX0006h13006h=56h, 13007h=78h.

POP: read, then increment

destination ← word at SS:SP
SP ← (SP + 2) mod 10000h

Continuing the example, POP DX produces DX=7856h and SP=0008h. The next POP AX produces AX=1234h and SP=000Ah. Popping changes the logical top; it does not erase the old bytes.

Operand restrictions and memory operands

push ax                   ; valid: 16-bit general register
push ds                   ; valid: segment register
push word ptr [di]        ; reads a word at DS:DI, pushes to SS:SP
pop word ptr [di+4]        ; pops to DS:(DI+4)
; push al                 ; invalid: byte operand
; pop dl                  ; invalid: byte operand
; push 1234h              ; no immediate PUSH on the original 8086
; pop cs                  ; not a supported documented POP destination

A memory operand's default segment follows its address expression. The stack side still uses SS:SP. For example, PUSH WORD PTR [BP+4] reads its source in SS, while PUSH WORD PTR [DI] normally reads its source in DS.

When preserving two values, reverse the register order on restoration: PUSH AX; PUSH BX; POP BX; POP AX. Popping AX before BX would exchange the saved values instead.

Lecture: 114:00–154:00. Source deck: Part2, slides 52–55. The simple formulas here cover ordinary operands; self-referential PUSH SP/POP SP cases are outside these exercises.

09 · Account for wraparound and preserve the state you need

SP wraps as a 16-bit offset

Keep offset arithmetic separate from physical address arithmetic. With SS=1300h and SP=0000h, a PUSH makes SP=FFFEh. The new physical top is 13000h + FFFEh = 22FFEh. It is not 12FFEh.

The segment's offset range 0000h..FFFFh corresponds to physical addresses 13000h..22FFFh. SP wrapping does not allocate memory or check capacity. A program must reserve enough stack space and prevent overwriting other data.

Predict the stack position

Two pushes from 000Ah leave SP=0006h.

This calculates pointer movement only. It does not simulate stack contents, check allocation or model special SP operands. The physical address is the resulting top, not necessarily the last address accessed.

PUSHF and POPF include FLAGS in the saved state

PUSHF pushes a FLAGS image, using two bytes of stack space. POPF pops that image back into the defined flags. PUSHF leaves flags unchanged; POPF changes them as part of the restoration.

preserve:
    push ax
    push bx
    pushf
    ; body may change AX, BX and arithmetic flags
    popf
    pop bx
    pop ax
    ret

Preserve values required by the caller, according to the routine's contract. FLAGS need saving when the caller depends on them across the call. A routine intended to return a result in AX must not blindly restore the old AX over that result.

A near CALL saves a return offset on the stack and RET uses it. Restore every value pushed inside the routine before RET, so the return address is at the top again. The live stack contains that return address as well as explicitly saved registers.

Lecture: 124:00–159:00. Source deck: Part2, slide 56. The example below uses a near CALL/RET pair; far-call syntax is not needed for this lesson.

10 · Use the implicit registers in I/O and table lookup

IN reads a port and OUT writes a port

I/O ports occupy an address space distinct from ordinary memory. IN AL,DX reads one byte from the port whose number is in DX. It does not copy DL into AL and does not read DS:DX.

InstructionPort addressTransferred value
IN AL,0F0hLiteral 00F0hOne byte into AL.
IN AX,DXThe full 16-bit DX valueOne word into AX.
OUT 20h,ALLiteral 0020hOne byte from AL.
OUT DX,AXThe full 16-bit DX valueOne word from AX.

A literal port number must fit in 00h..FFh. To use port 03F8h, write MOV DX,03F8h followed by IN AL,DX or the appropriate OUT. DX can also address a port below 0100h. AL versus AX chooses transfer width, independently of port-address width. IN and OUT leave FLAGS unchanged.

The value read and the effect of a write depend on the device. In emu8086, select a matching virtual device before experimenting. These syntax examples do not assume that every port has a meaningful device attached.

XLAT replaces an index with a byte from a table

AL ← byte at DS:[BX + unsigned old AL]

BX points to the table's first byte. The old AL is an unsigned index 0..255, with no implicit bounds check. The sum is an effective 16-bit offset. BX and FLAGS are unchanged; AL is replaced by the table entry.

Offset, with BX=0006h0006h0007h0008h0009h000Ah000Bh
Table byte11h22h33h44h55h66h

With DS=1300h and AL=03h, XLAT reads DS:0009h, physical address 13009h, and leaves AL=44h. The table is indexed from zero. If another lookup should use index 3, reload AL with 03h first: it now contains 44h.

The operand-free mnemonic is XLAT, also written XLATB by some assemblers. Its special BX+AL address does not make MOV AL,[BX+AL] a valid ordinary 8086 address form.

11 · Single-step three short emu8086 programs

Create a new COM program, replace the template with one complete example, then compile and emulate it. Step through each instruction and stop at the final comment before the main RET. Watch registers, FLAGS and the relevant memory bytes. These examples rely on the COM environment's initialized stack.

In programs A and C, scratch bytes at offset 0300h lie beyond the short code listing and below the initial COM stack. PUSH CS; POP DS makes DS refer to the program segment. The routines do not need external include files.

Program A: compare an address, a word and a far pointer

org 100h
push cs
pop ds
mov si, 0300h
mov byte ptr [si],   11h
mov byte ptr [si+1], 22h
mov byte ptr [si+2], 33h
mov byte ptr [si+3], 44h
lea dx, [si]
mov ax, [si]
les di, [si]
; Inspect here: DX=0300h, AX=2211h, DI=2211h, ES=4433h.
ret

Check DS:0300h..0303h for 11h,22h,33h,44h. LEA loads 0300h, MOV reads 2211h, and LES reads 2211h:4433h in offset-first storage order. ES changes, but no instruction then dereferences ES:DI.

Program B: preserve registers and the carry flag

org 100h
mov ax, 1234h
mov bx, 7856h
mov dx, sp
stc
call preserve
; Inspect here: AX=1234h, BX=7856h, CF=1, SP=DX.
ret

preserve:
    push ax
    push bx
    pushf
    mov ax, 0
    mov bx, 0
    add ax, 1
    popf
    pop bx
    pop ax
    ret

STC establishes CF=1 before CALL. Inside the routine, ADD clears CF for 0+1. POPF restores the original carry. The saved registers must be popped before RET. The SP comparison is made before the main RET returns to the COM environment.

Program C: look up a byte, then observe signed overflow

org 100h
push cs
pop ds
mov bx, 0300h
mov byte ptr [bx],   11h
mov byte ptr [bx+1], 22h
mov byte ptr [bx+2], 33h
mov byte ptr [bx+3], 44h
mov byte ptr [bx+4], 55h
mov byte ptr [bx+5], 66h
mov al, 03h
xlat
mov dl, al
mov al, 7Fh
add al, 1
; Inspect here: DL=44h, AL=80h, CF=0, OF=1.
ret

DL preserves the lookup result while AL is reused for arithmetic. ADD produces 80h: signed +127+1 overflows, but unsigned 127+1 still fits in a byte. This previews the next topic rather than assuming the clip taught the complete arithmetic instruction set.

Validation: the code paths and expected states were checked in a separate 16-bit x86 emulator. The listings have not been stepped through in the emu8086 application. That check verifies results, not original-8086 bus timing or undefined flag bits.

12 · Worked exercises

Predict the result on paper before opening the answer. Draw byte addresses for memory and stack problems.

01 · Repair the MOV instructions

Repair MOV ES,1234h, MOV [SI],[DI] for a word copy, and MOV AH,1234h without truncating the value.

Show worked answer

Use MOV AX,1234h; MOV ES,AX. For the word copy use MOV AX,[DI]; MOV [SI],AX. Use MOV AX,1234h for the full immediate. These replacements use or overwrite AX; preserve it separately if needed.

02 · Decode 8A 55 01

Identify the MOV operands and default source segment.

Show worked answer

8Ah is 10001010b, so d=1, w=0. 55h is 01 010 101: signed disp8, DL and DI. The instruction is MOV DL,[DI+1], reading DS:(DI+1).

03 · Encode a BP-relative word load

Encode MOV AX,[BP] using the register/memory family.

Show worked answer

Opcode 8Bh. mod=01, reg=AX=000, r/m=BP=110 gives 46h. Append 00h: 8B 46 00. It reads a word through SS:BP.

04 · Distinguish two displacement meanings

With SI=1000h, compare the addresses used by 88 8C F3 00 and 88 4C F3.

Show worked answer

The first uses disp16=00F3h and writes CL to DS:10F3h. The second sign-extends disp8=F3h to FFF3h and writes CL to DS:0FF3h.

05 · Predict a word exchange

AX=ABCDh. DS:0200h=34h and DS:0201h=12h. Execute XCHG AX,[0200h].

Show worked answer

AX=1234h. Memory becomes CDh at 0200h and ABh at 0201h. FLAGS is unchanged.

06 · Compare LEA, MOV and LES

DI=1111h. Starting from that same state each time, memory at DS:1111h..1114h is 11h,22h,33h,44h. Predict each of LEA DI,[DI], MOV DI,[DI] and LES DI,[DI].

Show worked answer

LEA gives DI=1111h. MOV gives DI=2211h. LES gives DI=2211h and ES=4433h. LEA/MOV leave ES unchanged. Each comparison starts from the original DI=1111h.

07 · Trace five pushes and one more

SS=1300h and SP=000Ah. Execute five ordinary word pushes, then a sixth. Give SP and the physical top after each stage.

Show worked answer

After five pushes SP=0000h and the top is 13000h. The sixth wraps SP to FFFEh and the top becomes 22FFEh. It is not a move to physical address 12FFEh.

08 · Pop into memory with a gap

SS:SP holds bytes 56h,78h,34h,12h in ascending address order. Execute POP WORD PTR [DI] and POP WORD PTR [DI+4]. Assume the destination does not overlap the source stack.

Show worked answer

DS:DI receives 56h, DS:(DI+1) receives 78h, DS:(DI+4) receives 34h and DS:(DI+5) receives 12h. The two bytes in the gap are unchanged and were not specified. SP increases by four.

09 · Preserve a condition across a helper

A caller depends on OF and AX after a helper that changes both. Is LAHF/SAHF sufficient?

Show worked answer

No. OF is outside the five flags transferred by LAHF/SAHF. Preserve AX with PUSH/POP and FLAGS with PUSHF/POPF in reverse order, provided the helper is not supposed to return its result in AX. Balance all pushes before RET.

10 · Choose the port and the lookup index

Read one byte from port 03F8h. Then, separately, predict XLAT for the table 11h,22h,33h,44h,55h,66h with AL=4.

Show worked answer

Use MOV DX,03F8h; IN AL,DX for the port. For a correctly initialized DS:BX table, index 4 is the fifth entry, so XLAT produces AL=55h. The two examples are independent.

13 · Knowledge check

Choose an answer for each question, then check your reasoning. The answer key also works without JavaScript.

1. Which displacement form represents the positive offset +0F3h?
2. What does LEA DX,[BX+DI+4] load?
3. A far pointer is stored as 11h,22h,33h,44h. What does LES DI,[pointer] load?
4. With SS=1300h, SP=0000h, where is the top after an ordinary PUSH?
5. Which flag is not restored by SAHF?
6. What selects the byte port-transfer width in IN AL,DX?
7. After XLAT reads table[3]=44h, what is AL?
8. Why does plain [BP] need a displacement in the usual MOV encoding?
Answer key for offline revision and printing

1. B. Positive 243 exceeds the signed disp8 limit of +127. The 16-bit bytes are F3 00.

2. A. LEA calculates the low 16 bits of the address expression and does not read memory.

3. C. Each word is little-endian. The offset word precedes the segment word.

4. B. Wrap the 16-bit offset first: 13000h + FFFEh = 22FFEh.

5. B. SAHF writes SF, ZF, AF, PF and CF. OF is outside the low byte.

6. C. AL requests a byte. DX supplies the port number, even for a low-numbered port.

7. B. XLAT replaces the old index in AL with the table byte.

8. A. Use mod=01,r/m=110 with a zero displacement for plain [BP].

Operand kindIs each operand a register, memory, immediate, effective address, pointer or port?

AddressWhich segment is selected? Which register values contribute to the offset?

Arithmetic is the next step

The clip ends while introducing arithmetic. ADD destination,source adds fixed-width bit patterns and updates CF, PF, AF, ZF, SF and OF. The same operation can be interpreted as signed or unsigned: CF reports unsigned carry, while OF reports signed overflow. ADD is not a signed-only instruction. Program C shows the distinction in one byte.

Corrections and boundaries

  • The encoding table above corrects the BP/SI/DI register entries in source slide 45.
  • The lecture’s written +0F3h displacement needs disp16. The byte F3h in disp8 means −13.
  • LAHF/SAHF cover five status flags. SAHF does not modify OF, and POPF is a flag-changing exception to broad claims that data-transfer instructions leave flags unchanged.
  • The stack demonstration wraps SP before calculating the physical address. Allocation and special SP operand behavior are outside the pointer calculator.
  • The examples use ordinary 8086 real-mode behavior. Later x86 instructions, cycle-accurate timing, live hardware I/O and full arithmetic coverage are outside this chapter.
