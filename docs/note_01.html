Microprocessor Study Guide · Chapter 01

8086 fundamentals: architecture, memory and addressing

A study and revision chapter for assembly beginners and microprocessor students. Each topic develops a concept, states its rules, works through examples and offers questions to test your understanding.

Scope: Intel 8088/8086, real mode, Intel/MASM syntax and emu8086.

00. Assembly language and how to study this chapter

What is assembly language?

Assembly language represents machine instructions using mnemonics such as MOV and ADD, together with register names such as AX. An assembler translates this source into machine-code bytes that the CPU executes. Instructions operate on particular registers and memory locations, so understanding the processor architecture helps you interpret a program correctly.

MOV AX, 1234h    ; load a 16-bit constant into AX
ADD AX, 1        ; add 1 to AX: AX becomes 1235h

This is Intel syntax: the destination comes first and the source comes second. A semicolon begins a comment extending to the end of the line. A mnemonic does not behave like an unrestricted high-level function: each instruction form has rules for its operands, width and affected flags.

Learning objectives

  • Interpret bit patterns as signed or unsigned numbers and combine bytes using little-endian order.
  • Explain how the CPU, memory, I/O and three types of bus cooperate.
  • Distinguish the BIU and EU and identify the register groups.
  • Calculate an effective address and convert segment:offset to a physical address.
  • Explain CF, OF and the remaining status flags after an 8-bit or 16-bit addition.
  • Read MOV instructions, select the default segment and predict which bytes are accessed.

Study route: read sections 01–05 to build the foundation, then 08–09 to understand memory operands. Study section 06 when starting arithmetic. Use 12–14 for revision. If number systems and registers are already familiar, begin with the memory examples and exercises.

Prerequisites: basic arithmetic, binary and hexadecimal notation. Previous knowledge of a high-level language is optional. Here, h marks hexadecimal and b marks binary; an unsuffixed constant is decimal in the syntax used by this chapter.

The chapter's sources appear under References. The explanations and exercises are designed to stand on their own.

01. One value, several representations

1.1. Bits, bytes, words and hexadecimal

A bit holds 0 or 1. A byte contains 8 bits. In this 8086 chapter, a word contains 16 bits, or two bytes. Each hexadecimal digit represents four bits: two hexadecimal digits describe a byte, and four describe a word.

Different notations for the same value
DecimalBinaryAssembly hex notation
1200001100b0Ch
4400101100b2Ch
12810000000b80h
25511111111b0FFh

For example, 1234h = 1 × 16³ + 2 × 16² + 3 × 16 + 4 = 4660 decimal. The suffix specifies the number base; it is not part of the stored value.

1.2. Little-endian orders bytes, not individual bits

The memory model used here is byte-addressable: each address identifies one byte. The word 1234h has a low byte of 34h and a high byte of 12h. Little-endian stores the low byte at the lower address.

Storing 1234h at 0100h; addresses increase down the table
AddressLittle-endianBig-endian
0100h34h — low byte12h — high byte
0101h12h — high byte34h — low byte

The four bytes of 12345678h appear at increasing addresses as 78h, 56h, 34h, 12h. To reconstruct the value, take the byte at the initial address as the low part and place later bytes above it.

Read address labels rather than page position. A diagram may put high addresses at the top or at the bottom. The rule remains: the low byte occupies the lower address.

Endianness matters when a value spans multiple bytes. It does not turn 34h into 43h or change the meaning of AX = 1234h. For that register value, AH=12h and AL=34h.

1.3. Signed and unsigned interpretation

An 8-bit unsigned number ranges from 0 to 255. An 8-bit signed number in two's complement ranges from −128 to +127. The pattern 80h means unsigned 128 or signed −128, depending on how it is interpreted.

WidthUnsigned rangeSigned two's-complement range
8 bits0…255−128…127
16 bits0…65535−32768…32767
n bits0…2ⁿ − 1−2ⁿ⁻¹…2ⁿ⁻¹ − 1

To encode −13 in 8 bits, write 13 as 00001101b, invert the bits to 11110010b, then add one: 11110011b = 0F3h. To interpret an 8-bit pattern whose most significant bit is 1, subtract 256 from its unsigned value: 243 − 256 = −13.

Try it: addresses 0200h and 0201h contain 78h and 56h. What word begins at 0200h?

5678h. The low byte is 78h and the high byte is 56h. A byte read at 0200h alone returns 78h.

02. The CPU belongs to a larger system

A microprocessor is the CPU. A microprocessor system also needs memory, I/O interfaces and connections between its components. A CPU alone is not a complete computer.

ComponentPurposeExample
CPUFetch, decode and execute instructions8088, 8086
MemoryStore instructions, data and intermediate resultsRAM, ROM
I/O interfaceAdapt signals and transactions between the processor and peripheralsKeyboard or display interface
BusesCarry addresses, data and control signalsAddress, data and read/write lines

Ordinary RAM is volatile: it loses its contents without power. SRAM retains bits using storage circuits, while DRAM requires periodic refresh. ROM-related memories such as EPROM, EEPROM and Flash retain data without power, but differ in how they are programmed and erased. The term ROM does not imply that every member of the family can never be rewritten.

2.1. Three buses answer three different questions

  • Address bus: which location is being accessed? With the CPU as bus master, it supplies the address to memory or I/O.
  • Data bus: which value is being transferred? Reads bring data into the CPU; writes send data out.
  • Control bus: what operation is requested, and is the transaction ready? Individual control lines have their own signal directions. A two-way arrow for the group does not make every wire bidirectional.

An 8-bit data bus transfers eight data bits per bus data transfer. A 20-bit address bus represents 2²⁰ distinct addresses. These widths describe different capabilities.

n address lines → 2ⁿ distinct addresses

For byte-addressable memory, 20 address lines cover 2²⁰ bytes = 1,048,576 bytes = 1 MiB, often called “1 MB” in older material. The address range is 00000h…FFFFFh. Address capacity describes what can be selected; it does not prove that all those locations contain installed RAM.

2.2. Follow a read or write transaction

  1. The CPU places the requested address on the address bus.
  2. It issues the appropriate read or write control signal.
  3. For a read, the selected component drives the data bus. For a write, the CPU supplies the data.
  4. The transfer completes according to the system's timing and readiness signals. A slow device can require waiting.

The conceptual instruction cycle is fetch → decode → execute: obtain instruction bytes, determine the operation and operands, then carry out the operation. Executing one instruction may require additional data reads or writes. An instruction cycle is not necessarily a single bus cycle or clock tick.

2.3. Interrupts and DMA

An interrupt requests a change in execution to service an event. When the CPU accepts the request, it saves the required return information and runs an interrupt handler. The handler can then return to the previous work. Maskable requests may be disabled or delayed; every request is not necessarily serviced immediately.

DMA allows a controller to transfer data between a peripheral and memory without CPU instructions moving every element. The CPU usually still sets up the operation and handles completion. Bus ownership must be coordinated; direct access does not eliminate the controller.

References: [1], [2].

03. The BIU handles the bus; the EU executes instructions

The 8088 and 8086 divide their work between two main units. The Bus Interface Unit (BIU) generates physical addresses, fetches instruction bytes and performs memory and I/O transactions. The Execution Unit (EU) receives instruction bytes from the queue, decodes them and executes operations using its control logic, ALU and registers.

Feature80888086
General registers and ALU16 bits16 bits
External data bus8 bits16 bits
Address bus20 bits20 bits
Instruction prefetch queue4 bytes6 bytes

The 8088 remains a 16-bit processor despite its 8-bit external data bus. Transferring a word over that bus needs two byte transfers. On the 8086, word-transfer behavior also depends on address alignment; a 16-bit operation does not guarantee a single bus cycle.

3.1. Why prefetching helps

While the EU performs an internal operation and the bus is available, the BIU can fetch bytes from the subsequent instruction stream. The EU can then consume bytes already in the queue instead of always waiting for a fresh fetch. This overlaps fetching with execution.

Separate the conceptual cycle from timing. Fetch, decode and execute describe tasks. On the 8086, overlapping fetch with execution does not mean three independent stages taking exactly one tick each, nor a guaranteed threefold speedup. Data accesses compete for the bus, and control transfers require the queue to be refilled for the new instruction stream.

Queue capacity is measured in bytes, not instructions. Six bytes may contain several short instructions or only part of a longer instruction sequence.

References: [1], [2].

04. Registers hold data and help locate it

The eight 16-bit general-purpose registers are AX, BX, CX, DX, SP, BP, SI and DI. For study, this section separates the four registers with accessible 8-bit halves from the pointer and index registers.

4.1. AX, BX, CX and DX

Register8-bit halvesCommon roles in specific instructions
AXAH / ALAccumulator; many multiply/divide and I/O forms use AX or AL
BXBH / BLBase register; can contribute to a memory operand's offset
CXCH / CLCount register; LOOP uses CX, and shift/rotate forms can use CL
DXDH / DLParticipates with AX in 16-bit multiply/divide; can hold an I/O port address

These registers can also hold ordinary data. Their conventional names do not require every addition to use AX or every counter to use CX.

MOV AX, 1234h    ; AH = 12h, AL = 34h
MOV AL, 56h      ; AX = 1256h; AH remains 12h
MOV AH, 0ABh     ; AX = AB56h

AH and AL are views of portions of AX, not three independent storage locations. Updating either half updates the corresponding part of AX. A 16-bit register need not be written with four explicit hexadecimal digits: MOV AX, 44h loads 0044h.

4.2. Segment, pointer and index registers

GroupRegisterPurpose
SegmentCSCode segment for the instruction stream
SegmentDSDefault data segment for many memory operands
SegmentSSStack segment
SegmentESExtra segment; destination segment for many string instructions
PointerIPInstruction offset within CS
PointerSPOffset of the stack top within SS
PointerBPBase pointer, commonly used to access data in SS
IndexSI, DISource/destination indices; also usable for addressing and data

A stack follows LIFO: the last item pushed is the first item popped. It commonly holds return information, saved values and temporary data. SP identifies the current position, while SS establishes the segment containing the stack.

4.3. Register pairs and their limits

  • CS:IP locates the instruction stream.
  • SS:SP locates the stack top; ordinary memory operands using BP default to SS.
  • DS:BX, DS:SI and DS:DI apply to ordinary memory addressing without BP.
  • For string instructions such as MOVS, the usual source is DS:SI and the destination is ES:DI.

DI does not always select ES. MOV AX, [DI] defaults to DS. ES:DI describes the destination of string instructions. Apply the rule for the actual instruction form.

References: [1], [2], [3].

05. Two 16-bit values locate a 20-bit address

5.1. Segment and offset

The 8086 has a 20-bit address space, but its segment and offset registers are 16 bits wide. An address is constructed from a segment value that establishes a base and an offset that counts bytes from that base.

Physical address = segment × 16 + offset = (segment << 4) + offset

In this real-mode chapter, segment:offset denotes a logical address. Multiplying the segment by 16 shifts it left four bits; in hexadecimal notation, append one zero. Thus 1000h × 16 = 10000h.

Logical address:  1000h:2345h
Segment base:     1000h × 10h = 10000h
Physical address: 10000h + 2345h = 12345h

Do not concatenate the text “1000” and “2345” or simply add the two 16-bit values. The segment register holds a value that must be scaled; it does not hold the physical base directly.

5.2. Segment size and overlap

A 16-bit offset ranges from 0000h to FFFFh, selecting 65,536 byte positions. A segment therefore spans up to 64 KiB. Increasing the segment value by one moves its base only 16 bytes, so segments can overlap.

SegmentBase addressAddress at offset FFFFh
0000h00000h0FFFFh
0001h00010h1000Fh
4900h49000h58FFFh

For an inclusive address interval, calculate its size as last − first + 1. The interval 49000h…58FFFh contains 10000h = 65,536 bytes. Omitting the final +1 loses one location.

5.3. Different logical addresses can identify one byte

Three representations of physical address 12345h
Segment:offsetCalculation
1000h:2345h10000h + 2345h = 12345h
1200h:0345h12000h + 0345h = 12345h
1004h:2305h10040h + 2305h = 12345h

If the physical address and segment are known, compute offset = physical address − segment × 16. For an ordinary nonwrapping calculation, the result must fit in 0000h…FFFFh. An arbitrary segment is not guaranteed to produce a valid offset for your chosen address.

At the address-space boundary: the arithmetic sum can exceed FFFFFh. The original 8086/8088 exposes only 20 address lines, so the bus carries the low 20 bits. FFFFh:0010h produces 100000h and wraps to 00000h on that bus. Do not apply this hardware rule unconditionally to later machines with A20 control.

Address calculator

Enter hex values from 0000 to FFFF: 1234, 1234h and 0x1234 are accepted. Models the original 8086/8088 with a 20-bit address bus.

1000h × 10h + 2345h = 12345h Address on the 20-bit bus: 12345h
Try it: if the segment base is 49000h, is the segment register 49000h or 4900h?

It is 4900h; 49000h is the physical base. If a question gives the physical base, add FFFFh to find the last byte of a full segment. If it gives the register value, multiply by 16 first.

06. Flags depend on both the operation and its width

FLAGS is a 16-bit register. The original 8086 has nine functional flags discussed here: six status flags and three control flags. Status flags describe results of instructions that update them. Not every instruction changes FLAGS.

AF — Auxiliary carryAddition carries from bit 3 to bit 4; subtraction borrows across that boundaryCF=1 does not imply AF=1

07. The address space includes more than application RAM

7.1. Major regions of the classic IBM PC model

The 1 MiB address space is assigned to different functions. The lower 640 KiB is conventional memory, containing system data, the operating system and application areas. The upper 384 KiB is reserved for display memory, ROM and other system mappings. Applications do not receive all 640 KiB as unused memory.

Important addresses in the classic PC model
Physical rangeSizePurpose
00000h…9FFFFh640 KiBConventional memory, including system data and programs
A0000h…FFFFFh384 KiBSystem area and hardware mappings
00000h…003FFh1 KiBInterrupt vector table
00400h…004FFh256 bytesBIOS data area
A0000h…BFFFFh128 KiB in the modelDisplay-memory address area; use depends on the adapter
F0000h…FFFFFh64 KiB in the modelBIOS ROM area
FFFF0hEntry addressFirst instruction fetch after reset

In real mode, the interrupt vector table has 256 entries of four bytes each. Each entry contains the handler's offset and segment: 256 × 4 = 1024 bytes. The table holds addresses of handlers, not the entire code for all 256 handlers.

Which details depend on configuration? DOS components, drivers, COMMAND.COM and application regions depend on the software version and loading arrangement. Their illustrative boundaries are not universal CPU requirements. COMMAND.COM interprets DOS commands; it is not an assembler translating every keystroke into machine code.

7.2. From reset to an application

  1. The original 8086/8088 resets with CS = FFFFh, IP = 0000h, identifying physical address FFFF0h.
  2. The instruction at that entry transfers control to BIOS initialization code in ROM.
  3. The BIOS checks and initializes hardware, the BIOS data area and interrupt vectors.
  4. It loads a boot program from storage into RAM and transfers control to it.
  5. The boot program loads the operating system, which can subsequently load applications.

The reset entry is near the top of the address space, not at 00000h. This description applies to the original processors in this chapter; later x86 reset behavior should be checked separately.

7.3. I/O ports have a separate address space

The 8086 has port addresses 0000h…FFFFh, providing 2¹⁶ distinct port addresses. This space is separate from memory addresses 00000h…FFFFFh. Port 20h is not automatically the memory byte at physical address 00020h.

IN and OUT access ports. DX can specify a 16-bit port address, while forms with an immediate port number encode an 8-bit address. COM1 at 03F8h, COM2 at 02F8h and LPT1 at 0378h are classic PC hardware conventions rather than requirements for every 8086 system.

References: [1], [2].

08. MOV copies the source into the destination

MOV destination, source → destination ← source value

MOV BX, DX copies DX into BX and leaves DX unchanged. It does not erase the source or exchange the operands. Distinguish an operand's kind from its current value.

NotationOperand kindMeaning
BXRegisterThe value currently in BX
1234hImmediateThe constant 1234h encoded in the instruction
[1234h]MemoryData at offset 1234h in the default segment
[BX]MemoryData at an offset given by the current BX value
MOV AX, 1234h      ; load a constant: AX = 1234h
MOV AX, [1234h]    ; read a word beginning at DS:1234h
MOV AX, BX         ; copy the value in BX
MOV AX, [BX]       ; read a word beginning at DS:BX

8.1. Check legality before calculating a result

  • The two data operands must have matching widths. MOV AL, BX is invalid: AL has 8 bits, BX has 16.
  • Ordinary MOV cannot have two memory operands. Copy through a register or use an appropriate string instruction.
  • An immediate constant cannot be loaded directly into a segment register: MOV DS, 0FF0h is invalid.
  • MOV cannot directly copy one segment register into another: MOV ES, DS is invalid.
  • MOV cannot write CS or IP. Use the appropriate control-transfer mechanism.
; Initialize DS through a 16-bit register
MOV AX, 0FF0h
MOV DS, AX

; Copy DS into ES through AX
MOV AX, DS
MOV ES, AX

These examples demonstrate valid syntax. Changing DS changes the physical region addressed by later data accesses, so initialize it according to your program's memory layout.

8.2. Specify memory width when it cannot be inferred

If the memory operand has no declared type, MOV [BX], 10 does not identify a byte or word write. State the intended width:

MOV BYTE PTR [BX], 10   ; write one byte: 0Ah
MOV WORD PTR [BX], 10   ; write two bytes: 0Ah, then 00h

MOV [BX], AL           ; AL determines a byte transfer
MOV [BX], AX           ; AX determines a word transfer

A typed variable can also allow the assembler to infer the size. Avoid depending on an unspecified tool default.

8.3. Decimal, hexadecimal and character constants

MOV BL, 44          ; decimal 44 → BL = 2Ch
MOV BL, 44h         ; hex 44h    → BL = 44h
MOV AL, 00001100b   ; decimal 12 → AL = 0Ch
MOV AL, 'A'         ; ASCII A    → AL = 41h
MOV AX, 0ABCDh      ; a hex constant beginning with a letter needs a leading 0

The leading zero in 0ABCDh lets the assembler recognize a number instead of an identifier in this syntax. It does not change the value. Uppercase 'A' is ASCII 41h; lowercase 'a' is 61h.

References: [2], [4].

09. Addressing modes describe where operands come from

For a memory operand, calculate the effective address (EA), select the segment and determine byte or word width. An addressing-mode name describes how the EA is formed. The seven categories below follow the course terminology.

ModeExampleEA / source locationDefault segment
RegisterMOV AL, BLSource is BLNo memory operand
ImmediateMOV AX, 44hSource is constant 44hNo memory operand in this example
DirectMOV AL, [1234h]1234hDS
Register indirectMOV AL, [BX]BXDS; BP-based access uses SS
Based relativeMOV AL, [BP+5]BP + 5SS; BX-based access uses DS
Indexed relativeMOV AX, [SI+10]SI + 10DS
Based indexed relativeMOV AX, [BX+SI+8]BX + SI + 8DS; expressions containing BP use SS

EA is a 16-bit offset, not the physical address. If adding its components exceeds FFFFh, retain the low 16 bits of the EA before adding the segment base. The examples below use offsets away from the segment boundary.

9.1. Direct addressing: the bracketed constant is an offset

Suppose DS = 1000h and memory[11234h] = 56h. For MOV AL, [1234h]:

  1. EA=1234h.
  2. The default segment is DS.
  3. The physical address is 1000h×16+1234h=11234h.
  4. AL is 8 bits, so one byte is read: AL=56h.

MOV AL, 1234h is a different request: loading an immediate that does not fit in AL. It is invalid for the stated width.

9.2. A word write occupies two consecutive bytes

; Assume DS already identifies valid data memory
MOV CX, 1234h
MOV [4320h], CX
; DS:4320h contains 34h
; the next byte, DS:4321h, contains 12h

MOV BX, [4320h]      ; BX = 1234h
MOV BL, [4320h]      ; BL = 34h
MOV BH, [4321h]      ; BH = 12h

The address in a word operand identifies its low byte. The high byte follows it at the next physical byte address. The data width determines the number of bytes accessed; the number of hexadecimal digits in the offset does not.

9.3. Indirect and relative forms use register values as offsets

In MOV AL, [BX], BX supplies an offset rather than the data copied directly into AL. In MOV AX, [SI+10], the unsuffixed 10 is decimal, so EA=SI+0Ah.

The assembler used here can interpret [BX]+10 and [BX+10] identically. Keeping the whole expression inside the brackets makes the memory operand easier to read.

9.4. DS, SS and segment overrides

  • An ordinary memory address containing BP defaults to SS.
  • The other ordinary memory forms considered here default to DS.
  • An explicit segment, such as ES:[BX] or DS:[BP+5], overrides the default where the instruction permits it.
MOV AL, [BX]        ; read DS:BX
MOV AL, ES:[BX]     ; read ES:BX
MOV CL, [BP+DI+5]   ; read SS:(BP + DI + 5)
MOV CL, DS:[BP+5]   ; explicitly use DS instead of SS

An override changes the segment base, not the EA formula. MOV AL, ES:[BX] does not add ES twice or replace BX with DI.

9.5. Combine EA, segment selection and endianness

Worked example. Let DS=1000h, SS=2000h, BX=0100h, SI=0010h, BP=0100h and DI=0010h. Memory bytes at 10118h, 10119h and 20115h contain 34h, 12h and 7Ah respectively.

MOV AX, [BX+SI+8]
; EA = 0100h + 0010h + 0008h = 0118h
; DS → first physical byte address = 10118h
; AL = 34h, AH = 12h → AX = 1234h

MOV CL, [BP+DI+5]
; EA = 0100h + 0010h + 0005h = 0115h
; BP selects SS → physical address = 20115h
; CL has 8 bits → CL = 7Ah; read one byte

9.6. Only certain registers and combinations form an EA

8086 memory addressing uses BX, BP, SI and DI. Encodable pairs include BX+SI, BX+DI, BP+SI and BP+DI, optionally with a displacement. Forms such as [AX], [SP], [BX+BP] and [SI+DI] are not valid 8086 memory addressing forms.

SP participates in stack operations, but this does not make MOV AX, [SP] valid on the 8086. Use a suitable BP-based or other legal addressing arrangement when accessing stack data.

Memory-operand checklist: identify the operand kind → determine the width → calculate EA → select the segment → calculate the physical address → read/write little-endian bytes → update only the flags affected by the instruction.

References: [1], [2], [4].

10. The assembler produces machine-code bytes

The CPU does not interpret the letters “MOV” as human-readable source. The assembler selects an encoding suitable for the operands and emits bytes describing the operation, registers, address calculation and any required constants.

10.1. Fields in the register ↔ memory MOV form

For this MOV form, the first byte is 100010 d w. The second is mod reg r/m, with fields of two, three and three bits.

  • w=0 selects byte data; w=1 selects word data.
  • d=1 makes REG the destination; d=0 makes REG the source.
  • mod selects memory/displacement behavior or a register operand.
  • reg names a register; r/m names a register or an EA form.
MODMeaning in this form
00Memory, usually without displacement; R/M=110 is the special direct 16-bit address form
01Memory with a signed 8-bit displacement
10Memory with a 16-bit displacement
11R/M identifies a register, not memory

The d/w interpretation is specific to this encoding family. Immediate-to-register MOV uses another form. Instruction length depends on the encoding, displacement, immediate data and prefixes; a single fixed diagram does not describe every instruction stream.

10.2. Encode MOV CL, [BX]

  1. Select the MOV form 100010dw.
  2. CL is a byte register → w=0.
  3. Data goes to CL → d=1.
  4. [BX] has no displacement → mod=00.
  5. CL is reg=001; [BX] is r/m=111.
Byte 1: 100010 1 0 = 10001010b = 8Ah
Byte 2: 00 001 111 = 00001111b = 0Fh

MOV CL, [BX] → 8A 0F

This instruction occupies two code bytes but reads one data byte. Instruction length and operand width are separate properties. A two-byte instruction does not necessarily access a word.

Reference: [2].

mov ah, byte ptr [sample+1]AH=12h; AX=1234h

After loading AL alone, do not assume AX=0034h. AX previously received CS, and an AL write leaves AH unchanged.

11.2. Compare the two additions

org 100h

mov al, 80h
mov ah, 80h
add al, ah        ; stop: AL=00h, CF=1, OF=1, ZF=1

mov ax, 0080h
mov bx, 0080h
add ax, bx        ; stop: AX=0100h, CF=0, OF=0, ZF=0
ret

Record all six status flags after the first ADD. The intervening MOV instructions do not recalculate them. Step through the second ADD before comparing the new flags. Change the operands or width and explain the differences.

If the result differs from your prediction, what should you check first?
  1. Are you stopped before or after the instruction?
  2. Is the displayed number hexadecimal or decimal?
  3. Are you examining AX or only AL/AH?
  4. Was DS initialized correctly?
  5. Are you reading a byte or a word, and at which offset?
  6. Do the displayed flags belong to the last ADD or an earlier instruction?

12. Exercises with worked answers

Apply the chapter's rules and write an explanation before opening each answer. If the question omits required data, state what can be determined and what remains unknown.

Exercise 1 — Reconstruct a word

DS:0200h contains CDh and DS:0201h contains ABh. Execute MOV AX, [0200h]. Find AX, AH and AL.

Answer to exercise 1

AL=CDh, AH=ABh and AX=ABCDh. The byte at the lower address supplies the low part of the word.

Exercise 2 — An address is not the data at that address

BX=1234h, DS=1000h and the byte at physical address 11234h is 56h. Compare MOV AX, BX and MOV AL, [BX], considering each independently.

Answer to exercise 2

The first sets AX=1234h. The second sets AL=56h by reading 10000h+1234h=11234h. The second does not load 34h and tells you nothing about the previous AH value.

Exercise 3 — Calculate a physical address

DS=1234h and SI=7890h. Which physical address does MOV AL, [SI] read?

Answer to exercise 3

1234h×10h+7890h=12340h+7890h=19BD0h. Without the memory contents, AL's resulting value is unknown.

Exercise 4 — Find an offset and segment boundary

The physical address is 12345h and the segment is 1200h. Find the offset. Then find the final byte address of a full 64 KiB segment whose physical base is 49000h, without wrapping past 1 MiB.

Answer to exercise 4

Offset=12345h−12000h=0345h. The last address is 49000h+FFFFh=58FFFh. The inclusive size is 58FFFh−49000h+1=10000h bytes.

Exercise 5 — BP selects the default segment

DS=1000h, SS=2000h, BP=0100h and DI=0010h. Where does MOV CL, [BP+DI+5] read, and how many bytes?

Answer to exercise 5

EA=0115h. BP selects SS, giving physical address 20000h+0115h=20115h. CL has 8 bits, so one byte is read. DS is not used in this calculation.

Exercise 6 — Distinguish CF from OF

AL=7Fh. Execute ADD AL, 1. Find AL and all six status flags.

Answer to exercise 6

AL=80h. CF=0; OF=1; SF=1; ZF=0; AF=1 because Fh+1 carries into bit 4; PF=0 because 80h has one set bit. Signed +127+1 overflows, while unsigned 127+1 fits.

Exercise 7 — Parity examines the low byte

AX=00FFh. Execute ADD AX, 1. Find the result, ZF, PF and AF.

Answer to exercise 7

AX=0100h; ZF=0 because the word is nonzero; PF=1 because the low byte 00h contains zero set bits; AF=1 because Fh+1 carries. The set bit in the high byte does not affect PF.

Exercise 8 — Find invalid instruction forms

MOV AL, BX
MOV ES, DS
MOV DS, 1234h
MOV AX, [SP]
MOV [BX], [SI]
Answer to exercise 8
  • AL/BX have different widths; use MOV AL, BL if the goal is to copy BX's low byte.
  • ES/DS need an intermediate 16-bit register.
  • Load 1234h into AX, then use MOV DS, AX.
  • [SP] is not an 8086 EA form. Design a suitable BP-based or other valid access; changing a register name arbitrarily can change the address.
  • MOV does not permit two memory operands. Copy through a register and specify the intended data width.

Exercise 9 — Is there enough information?

DS=1000h, BX=0100h. The instruction is MOV AX, [BX], but memory contents are unspecified. What can you determine?

Answer to exercise 9

The mode is register indirect; the segment is DS; EA=0100h; the first physical address is 10100h. Two bytes at 10100h and 10101h are read in little-endian order. AX's resulting value is unknown. MOV does not modify the status flags.

Exercise 10 — Code length versus data width

MOV CL, [BX] encodes as 8A 0F. What is its instruction length, and how many data bytes does it read?

Answer to exercise 10

It has two instruction bytes and reads one data byte because CL is an 8-bit register. Fetching instruction bytes is separate from reading the data operand.

Terminology

MSB/LSB: most/least significant bit. Nibble: four bits. Operand: an instruction's data or data-location argument. Immediate: a constant encoded in an instruction. Displacement: a constant added when forming an EA. EA: effective address, the calculated offset. Opcode: operation code. Assembler: software translating assembly source. ISR: interrupt service routine. Prefetch: fetching instruction bytes ahead of execution.
