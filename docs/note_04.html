From 8086 segments to protected mode

Understand selectors, descriptors and bounds, then practice the state-tracing skills behind memory, stack, flag, loop and representation problems.

Scope: session 4 (06/04) · x86 evolution and protected-mode concepts · 8086 real-mode practice · Intel/MASM syntax.

00 · Connect the 8086 model to later x86 processors

A segment register can hold the same number of bits while changing what that number means. In 8086 real mode, its value helps calculate a base address directly. In protected mode, its visible value selects a descriptor containing a base, limit and access policy. Understanding that change is the central new idea of this session.

The second half develops a reliable method for revision problems: state the width, find implicit operands, follow byte addresses, and track which instruction last wrote a flag. Review note 01 for representation and addressing, note 02 for data transfer and stacks, and note 03 for arithmetic and control flow.

  • Separate processor width, register width, bus width and address-space size.
  • Decode a selector and find its descriptor’s byte position.
  • Calculate segment bounds without confusing a limit with a size.
  • Distinguish a logical address, linear address and physical address.
  • Solve stack, flag, loop and number-representation exercises by tracing state.

01 · A wider processor does not widen every register

Compatibility preserves useful names and operations while adding new capabilities. Keep four quantities separate: the width of a data operation, the width of a register, the number of address bits, and the amount of installed memory.

Model / execution contextGeneral-purpose registersFlags registerVisible segment valuesMemory-management change
8086 / 8088Eight 16-bit registers; four have named byte halves.16-bit FLAGSFour × 16 bits: CS, DS, SS, ES.20-bit physical addressing; real-mode segments.
8018616 bits16-bit FLAGSFour × 16 bitsRetains the 8086-style address model; integrates more peripheral functions and adds instructions.
8028616 bits16-bit FLAGS, with additional system fieldsFour × 16 bitsAdds protected mode and 24-bit physical addressing.
8038632 bits: EAX…EDI32-bit EFLAGSSix × 16 bits: adds FS and GS.32-bit linear addresses, expanded descriptors and optional paging; the 386DX has a 32-bit physical address bus.
Intel 64, in 64-bit mode64 bits: RAX…R1564-bit RFLAGS representationVisible selectors remain 16 bits.Uses a different 64-bit execution/address model; implemented address widths depend on the processor.

Correct the width at the transition point. The 80286 does not have a 32-bit EFLAGS register. The 80386 introduces EFLAGS. A 64-bit general-purpose register also does not imply a 64-bit CS or DS selector, a 64-bit external address bus, or 2⁶⁴ bytes of installed RAM.

The lecture uses a later Pentium 4 example to introduce 64-bit register names. Treat this as the model of a processor supporting Intel 64, rather than assuming that every processor sold under a broad family name supports every later extension. The emu8086 practice programs below remain strictly 16-bit.

02 · Register names select overlapping parts of one value

AX, AH and AL are overlapping views, not three independent storage locations. AX consists of AH as bits 15–8 and AL as bits 7–0. Changing one byte changes that part of AX while preserving its other byte.

Starting AX=1234h each timeResultReason
MOV AL,56hAX=1256hReplace only the low byte.
MOV AH,78hAX=7834hReplace only the high byte.
MOV AX,0ABCDhAH=ABh, AL=CDhReplace both bytes through the word view.

On the 80386, AX is the low 16 bits of EAX. EAX=12345678h therefore gives AX=5678h, AH=56h and AL=78h. The high 16 bits of EAX do not acquire a separately named “high EAX” register. The old byte names belong to AX/BX/CX/DX, not to arbitrary halves of every register.

In 64-bit mode, RAX contains EAX and AX as smaller views. One additional rule matters there: writing EAX clears the upper 32 bits of RAX, while a write to AX does not clear all the remaining bits. That is a later execution-mode rule; it is not behavior to expect from an 8086.

Legacy x87 data registers have an 80-bit extended-precision representation; MMX and XMM register widths describe other facilities. They do not redefine the width of AX or CS. Keep a register’s role and execution mode next to its name.

03 · The mode changes how segment:offset is interpreted

8086 real mode: calculate the segment base directly

For an ordinary 8086 memory access, physical address=(segment×16+offset) modulo 2²⁰. The segment value supplies a base aligned to 16 bytes; a 16-bit offset selects a byte within a 64-KiB address window. Real mode provides no descriptor-based isolation between applications.

Protected mode: find the base through a descriptor

A logical address contains a selector and offset. The selector identifies a descriptor in a table. That descriptor supplies the base, bounds and attributes. Once the access is allowed, segmentation adds the offset to the selected base to produce a linear address. On the 80286, which has no paging, this reaches the physical address. On the 80386, paging can add another translation stage.

StepReal-mode exampleProtected-mode example, paging absent
Visible pair8123h:FFECh0058h:FFECh
Obtain base8123h×10h=81230hGDT entry 11 stores base=81230h.
Add offset81230h+FFECh=9121Ch81230h+FFECh=9121Ch, if bounds/rights permit.

The same numeric selector can identify a different base when the active tables change. Conversely, multiple descriptors can describe overlapping regions. A selector is neither a physical address nor a quantity to multiply by 16 in protected mode.

04 · Decode index, TI and RPL before doing address arithmetic

A selector has three fields. Decode them independently before looking up any descriptor:

FieldBitsCalculation from a 16-bit selector
Index15…3selector >> 3
TI, table indicator2(selector >> 2) AND 1: 0=GDT, 1=current LDT.
RPL, requested privilege level1…0selector AND 3: values 0…3. Lower numbers denote higher privilege.

For selector 0058h, index=11, TI=0 and RPL=0. Every descriptor is eight bytes, so its byte offset in the GDT is 11×8=58h. If the GDT’s base linear address is 00001000h, the descriptor occupies linear addresses 00001058h–0000105Fh.

For 005Fh, index is still 11 and the entry offset is still 58h, but TI=1 selects the LDT and RPL=3. Adding the full selector 5Fh to the table base would incorrectly include the low control bits as if they were part of an entry offset.

Check the table boundary too

There are 2¹³=8192 possible indices, but a table may be shorter than 64 KiB. A descriptor lookup requires index×8+7 ≤ table limit. The GDT’s entry 0 is reserved: selectors with index=0 and TI=0 are null selectors, including 0000h–0003h. LDT entry 0 is not automatically null.

GDTR identifies the GDT. LDTR identifies the active LDT and its cached information. When a segment register is loaded successfully, the processor caches the descriptor’s base, limit and attributes; it does not reread the entire table for every subsequent byte access.

05 · A descriptor stores a base, last valid offset and access policy

The 80286’s ordinary code/data descriptor occupies eight bytes. A 24-bit base identifies the beginning of a segment within its 16-MiB physical address space. The 16-bit limit gives the final permitted offset for an ordinary expand-up segment. Access fields describe whether and how the segment can be used.

Descriptor fieldWidth / positionMeaning in this chapter
Limit16 bits, bytes 0–1Last valid offset, from 0000h through FFFFh.
Base24 bits, bytes 2–4Starting address; low word followed by high base byte.
Access rightsByte 5Includes present, privilege and type information.
ReservedBytes 6–7Not an extension to the base/limit in the 80286 format.

A limit is not the same thing as a length

For base=00123000h and limit=01FFh, valid offsets run from 0000h through 01FFh inclusive: 512 bytes. A byte at offset 01FFh is valid. A word beginning there is not: its second byte would be at offset 0200h.

More generally, for an access of w bytes starting at offset o, an ordinary expand-up segment requires o+w−1 ≤ effective limit, without allowing the end calculation to wrap back into range. A 16-bit limit of FFFFh describes 65536 bytes, not 65535.

Decode the stored bytes

For bytes FF 01 00 30 12 92 00 00 in ascending addresses, the limit word is 01FFh; the base is 12h:3000h, assembled as 00123000h. Access byte 92h describes a present, writable data segment at DPL=0. A word at offset 01FEh occupies addresses 001231FEh–001231FFh and fits; a word at 01FFh crosses the bound.

These examples deliberately use expand-up code/data segments. Expand-down segments, stack-specific checks, gates and system descriptors have additional rules and are outside this introductory model.

06 · Granularity changes the scale of a 20-bit limit

The 80386 expands the base to 32 bits and the stored limit to 20 bits. The G bit tells the processor how to turn that stored limit into the final byte offset. This is separate from the D/B bit’s operand/address-size or stack-related role.

GEffective last-byte offsetSize of an ordinary expand-up segment
0Raw limitRaw limit + 1 bytes.
1Raw limit×4096 + 4095(Raw limit + 1)×4096 bytes.
Raw limitGEffective limitByte count
00000h000000000h1
00000h100000FFFh4096 (4 KiB)
00001h100001FFFh8192 (8 KiB)
FFFFFh0000FFFFFh1048576 (1 MiB)
FFFFFh1FFFFFFFFh4294967296 (4 GiB)

Do not merely append three zero hex digits to obtain a byte limit when G=1. The low twelve bits of the effective limit are ones, because it names the last included byte. Multiplying by 4096 alone gives the start of the last 4-KiB block.

Read a full-range descriptor

The eight bytes FF FF 00 00 00 92 CF 00 give base=00000000h. The low limit word FFFFh and high nibble F combine into raw limit FFFFFh. Byte CFh sets G=1 and D/B=1, giving an effective limit FFFFFFFFh. This describes a 4-GiB segment-relative range; defining it does not allocate 4 GiB of RAM or populate page tables.

Selector and segment-bound calculator

All address fields are hexadecimal; access length is decimal. Supply an ordinary 80386 expand-up descriptor manually. This checks selector fields and segment bounds; it does not load a real GDT/LDT, check table size or privileges, or translate page tables.

Selector 0058h → GDT index 11, RPL=0; descriptor byte offset 0058h. Base 00081230h + offset 0000FFECh → linear 0009121Ch. Access is within the supplied segment limit.

07 · Protection is an access check, not just a larger address

A descriptor gives the processor enough information to reject certain accesses. For example, it can distinguish an executable code segment from a data segment, require appropriate privilege, mark a segment not present, and limit the permitted offsets.

QuestionWhat to inspectExample rejection
Does the descriptor exist within the table?Index and table limit.An entry extends beyond the configured GDT/LDT.
Is it available?Present bit.A non-present segment cannot be used as if resident.
Does its type allow this use?Descriptor type and relevant access attributes.Attempting to write through a read-only data segment.
Is privilege sufficient?CPL, RPL and descriptor DPL.A less-privileged request attempts an ordinary access to a more-privileged data segment.
Is the entire operand within the segment?Offset, access width and effective limit.A two-byte read starts at the final permitted byte.

For an ordinary data-segment load, a useful rule is max(CPL,RPL) ≤ DPL, alongside the type and presence requirements. For example, CPL=3 and RPL=0 still cannot load an ordinary DPL=0 data segment: putting 0 in RPL does not grant kernel privilege. Code transfers, conforming segments and SS have distinct rules.

The source deck describes the GDT as global and an LDT as local to a program. These names describe table organization, not a universal promise of access. A GDT entry can describe restricted data, and systems software can arrange shared regions. Protection works through descriptor attributes and privilege checks.

Similarly, “code cannot be read as data” is too broad. A code segment can be marked readable; what is permitted depends on its type and privileges. An access violation raises an exception rather than silently converting the selector into a real-mode base.

08 · Separate segment naming, linear space and physical memory

The lecture multiplies table entries by maximum segment size to describe a large segmented naming space. That arithmetic should not be mistaken for the number of distinct bytes of physical RAM, or for a single flat linear address space.

QuantityCalculationInterpretation
8086 byte-address space2²⁰=1048576 bytes1 MiB of physical address space; not a promise that every address contains RAM.
80286 physical address space2²⁴=16777216 bytes16 MiB.
80286 textbook segmented estimate2 tables×8192 entries×64 KiB1 GiB as an idealized sum of selector/segment ranges.
80386 linear address space2³² bytes4 GiB in one linear address space.
80386 textbook segmented estimate2 tables×8192 entries×4 GiB64 TiB as an idealized aggregate of segment-relative ranges.

The estimates ignore the reserved null GDT entry, descriptors used for system structures, shorter configured tables, and overlap between mapped regions. They are a way to understand the selector/offset model. The 64-TiB sum does not turn 32-bit linear addressing into a 64-TiB flat space.

Paging is a second translation on the 80386

With paging disabled, linear addresses go directly to physical addressing. With paging enabled, page tables map linear addresses to physical page frames and may enforce additional permissions. Consequently, descriptor base + offset produces a linear address; calling that value physical is valid only when paging is absent or the mapping is known.

LinearDescriptor base + offset, after segment checks
→
PhysicalPage translation, if enabled

Virtual memory involves mappings, availability and operating-system policies. Merely observing that a sum exceeds installed RAM is not a complete description of how virtual memory works. Protected mode and paging are related facilities, but the 80286 demonstrates that protected mode can exist without paging.

09 · Solve memory operands in the order width → offset → segment

For revision problems, record the operand width first. Then calculate the 16-bit effective offset, select the default or overridden segment, calculate the physical address, and read the required number of bytes in little-endian order.

Ordinary 8086 expressionDefault segmentWhy
[BX+2]DSNo BP in the effective address.
[BP+SI+30]SSThe expression includes BP. Unmarked 30 is decimal (1Eh).
[DI]DSAn ordinary memory operand through DI is not automatically ES:DI.
ES:[BP+2]ESAn explicit segment override replaces the ordinary default.

Do not change the radix halfway through

For BP=110Ch and SI=1002h, [BP+SI+30] has offset 110Ch+1002h+001Eh=212Ch. With SS=2000h, the physical address is 2212Ch. Writing 30h instead would use 48 decimal and produce a different address.

A word load reads two consecutive bytes

With BX=0004h, byte DS:0006h=B8h and byte DS:0007h=90h, MOV AX,[BX+2] loads AX=90B8h. AL receives B8h and AH receives 90h. If the instruction were MOV AL,[BX+2], only B8h would be read into AL and the old AH would remain.

The ModR/M mod bits distinguish register mode and displacement forms; r/m selects the addressing expression, with the direct-address exception for mod=00,r/m=110. Remember that an 8-bit displacement is signed. The detailed encodings remain in note 02.

10 · A saved BP lets you name bytes after SP moves

PUSH decrements SP by two before storing a word. The high byte sits one address above the low byte. BP can retain the old stack position while later pushes move SP downward. A BP-based memory operand uses SS by default.

; Assume the initial SP is S; BP is assigned before these pushes.
mov cx, 2F3Dh
mov bp, sp
mov ax, 011Ah
push ax
push cx
mov al, [bp-3]      ; AL=2Fh
Stack offset relative to old SP / BPByte after both pushesMeaning
BP−43DhLow byte of the last pushed word, CX. New SP points here.
BP−32FhHigh byte of CX; selected by MOV AL,[BP−3].
BP−21AhLow byte of the first pushed word, AX.
BP−101hHigh byte of the first pushed word, AX.

The answer is 2Fh, not 3Dh: one byte above the top contains the high byte of CX. The MOV itself does not pop a value, so SP remains at BP−4. Restore SP or balance the pushes before returning from a routine.

A near CALL pushes the return IP; a far CALL pushes return CS and IP. An interrupt frame additionally saves FLAGS. Do not count “one register” as “one byte”, and do not assume a CALL preserves all ordinary registers. See note 03 for the complete near/far distinction.

11 · Choose an instruction that asks the intended question

Many multiple-choice traps substitute a value-changing instruction for a test, or inspect a flag that does not encode the requested condition. State the question in plain language before choosing the mnemonic.

Question / taskSuitable instructionWhy the similar-looking alternative fails
Is AL zero, without changing AL?TEST AL,AL or CMP AL,0, then JZ/JNZ.CMP AL,AL always finds equality. XOR AL,AL changes AL.
Are AX and BX different?CMP AX,BX or XOR AX,BX, then JNZ; prefer CMP if AX must survive.JNC after XOR is always true because XOR clears CF; it is not an inequality test.
Is bit 2 of AL set?TEST AL,04h, then JNZ.AND AL,04h changes all the other bits.
Clear bit 2 while preserving other bits.AND AL,0FBhTEST never stores the masked result.
Is the byte at DS:2000h zero?CMP BYTE PTR [2000h],0Two memory operands are not a legal TEST/CMP pair. Without h, 2000 is decimal.
Is an unsigned word even?TEST AX,1, then JZ.DIV by 2 can work with a prepared dividend, but is unnecessary and overwrites quotient/remainder registers.

Bit positions are numbered from zero: bit 2 has mask 00000100b=04h. The mask to clear it is 11111011b=FBh. A quoted character is different from an integer: '9' is ASCII 39h, while numeric 9 is 09h.

TEST/XOR/AND clear CF and OF; they set SF/ZF/PF from the logical result and leave AF undefined. CMP uses subtraction flags. Equality uses ZF; unsigned order uses CF/ZF; signed order uses SF, OF and ZF. A following branch sees the most recent relevant flags, not the original operands magically.

12 · Trace a flag producer before its consumer

SHL produces a new carry

In the following fully specified example, an earlier CLC or STC does not change the answer. SHL inserts zero, and writes CF from the old high bit of AL.

mov ax, 78F9h      ; AH=78h, AL=F9h
shl al, 1          ; AL=F2h, CF=1
adc ah, 2          ; AH=78h+2+1=7Bh; AX=7BF2h

The incoming carry of ADC is the outgoing carry of SHL. After ADC, CF/OF/SF/ZF/AF/PF belong to the AH addition; they no longer all describe the preceding shift.

RCL also consumes the incoming carry

mov ax, 0C4F1h
stc                ; incoming CF=1 matters for RCL
mov cl, 2
rcl al, cl         ; F1h -> E3h -> C7h; final CF=1
adc ah, 0          ; C4h+0+1=C5h; AX=C5C7h
StageALAHCFOF
Initial after STCF1hC4h1Not specified by the setup.
After one conceptual RCL stepE3hC4h1Do not use an intermediate step to define multibit-instruction OF.
After RCL AL,CL with CL=2C7hC4h1Undefined.
After ADC AH,0C7hC5h00, from the new ADC.

Native 8086 shift/rotate counts are 1 or CL. The multibit RCL leaves OF undefined, but ADC defines a new OF. This does not make the earlier undefined value a problem, because ADC reads CF rather than OF.

Recheck signed overflow without relying on the result sign

For an 8-bit D4h−5Dh=77h: unsigned 212−93=119 fits, so CF=0. Signed −44−93=−137 does not fit in −128…127, so OF=1. AF=1, SF=0, ZF=0 and PF=1. A positive stored result can accompany signed overflow.

13 · CX counts iterations while CL may also control the body

In 16-bit 8086 code, LOOP decrements the entire CX, then branches if CX is nonzero. It preserves FLAGS. CL is the low byte of CX, so a body using CL as a shift count observes that changing counter.

mov ax, 00FFh
mov cx, 2          ; explicitly initializes CH=0 as well as CL=2
again:
shl ax, cl
loop again
; AX=07F8h, CX=0000h
Body entryCX / CL before SHLAX after SHLCX after LOOP
First0002h / 203FCh: shift twice.0001h, so branch.
Second0001h / 107F8h: shift once.0000h, so stop.

The total number of bit shifts is 2+1=3, rather than 2×2. Also, MOV CL,2 alone does not clear CH. A previously nonzero CH would cause a different number of iterations.

A reset inside the loop can prevent termination

again:
mov cl, 2          ; reset on every visit
dec cl             ; CL becomes 1
jnz again          ; always repeats: DEC always leaves ZF=0

Moving the initialization before the label changes the behavior. This reset example uses DEC/JNZ, while the variable-shift example uses LOOP; write down which register and flags each one actually changes.

Count writes separately from bit-pattern changes

mov ch, 1
mov cl, 4          ; CX=0104h=260 decimal
count_again:
loop count_again   ; 260 executions, ending at CX=0

LOOP performs 260 decrements of CX and therefore 260 changes of its low byte, including a wrap from 00h to FFh. Including the executed MOV CL,4 gives 261 writes/assignments to CL. Calling those 261 actual value changes additionally assumes that CL was not already 4 before the MOV. Define what is being counted before choosing an answer.

For a general counted loop, guard the body with JCXZ if an initial CX=0 should mean no work. Without a guard, entering a LOOP body at zero can produce 65536 iterations.

14 · Keep integers, characters and floating-point fields separate

Two’s complement depends on the width

For an 8-bit −63, start with +63=00111111b. Invert to 11000000b, add 1, and obtain 11000001b=C1h. The same signed value as a 16-bit word is FFC1h. Without a width, “the binary representation of −63” is incomplete.

Hexadecimal carry and borrow use a base of sixteen

A hexadecimal digit A means ten and B means eleven. A+B=21 decimal=15h: write 5 and carry 1 to the next hex column. For a borrow, one unit from the next column supplies sixteen units to the current column.

1000h
- 0234h
-------
  0DCCh

Check: 0234h + 0DCCh = 1000h.

Use decimal as a check when useful, but keep the base consistent within each written calculation. Do not silently treat a quoted ASCII digit or a hex suffix as decoration.

For two negatives, greater magnitude means a smaller numerical value. Exponent fields 0 and 255 require special interpretation.

15 · Match a processor to a workload, then state the assumptions

The lecture’s conceptual questions connect video processing with specialized signal-processing hardware and connect multicore processors with parallel work. Use those as a starting point for reasoning, rather than as a universal ranking of product categories.

Workload characteristicRelevant capabilityQuestion to ask
Repeated operations on many pixels or samplesData-parallel or signal-processing hardware, such as GPU/DSP functions.Can the algorithm use that parallelism, and what are its data-transfer costs?
Independent tasksMultiple execution cores.How much work can run independently, and what remains serial?
General control and mixed softwareGeneral-purpose execution and suitable software support.Does the platform meet latency, memory and energy requirements?
A small embedded control taskTimers, I/O and integration appropriate to the task.What resources are actually required?

More cores do not automatically accelerate a serial instruction stream. A higher clock frequency is not by itself a complete performance measure. Modern microcontrollers and system-on-chip devices also differ widely, so “all microcontrollers are too slow for images” is not a useful general law.

For an exam question, read the stated options and assumptions. For a real design, define workload, deadlines, memory, energy and software constraints before selecting hardware. This chapter explains the decision variables; it does not recommend a current product.

16 · Five complete emu8086 practice programs

Use one listing per COM program. The COM template supplies the initial environment and stack. Stop at the checkpoints before the final RET. These programs exercise ordinary 8086 real-mode code; the protected-mode descriptor calculator is a teaching model and cannot enable protected mode in emu8086.

loop again
; Checkpoint: AX=07F8h, CX=0; OF=0 from the final one-bit shift
ret

The first body shifts by 2 and the second by 1. LOOP preserves the flags left by the shift; it does not set a new ZF for CX.

C · Test a bit, then clear it deliberately

org 100h
mov al, 05h
mov bl, 0
test al, 04h
jz bit_was_clear
mov bl, 1
bit_was_clear:
and al, 0FBh
; Checkpoint: BL=1 records the old bit; AL=01h after clearing bit 2
ret

TEST leaves AL intact for the decision. AND then performs the requested modification. These are separate responsibilities.

D · Accumulate 1 through hexadecimal 12h

org 100h
xor ax, ax
again:
inc al
add ah, al
cmp al, 12h
jne again
; Checkpoint: AL=12h (18), AH=ABh (171), AX=AB12h
ret

The loop adds the new AL before testing equality, so 18 is included. The sum is 18×19/2=171, which fits in an unsigned byte. Final flags describe CMP, not the last addition.

E · Pass carry from a rotation to ADC

org 100h
mov ax, 0C4F1h
stc
mov cl, 2
rcl al, cl
adc ah, 0
; Checkpoint: AX=C5C7h, CF=0, OF=0 from ADC
ret

RCL produces CF=1 after rotating F1h through the initial carry twice. ADC consumes that CF and defines its own new flags.

Program outcomes and stack balance were checked with a separate 16-bit assembler/emulator. They have not been stepped through in the emu8086 application. No protected-mode boot code, hardware timing or live peripheral I/O is claimed to have been tested.

17 · Worked revision exercises

State assumptions and predict the result before opening the answer. For memory questions, write byte addresses. For flags, identify the instruction that last produced the condition.

01 · Identify the width that matters

An application uses a 64-bit-capable x86 processor. Must CS contain a 64-bit selector?

Show worked answer

No. The visible segment selector is 16 bits. General-purpose register width and segment-selector width are different properties.

02 · Read overlapping registers

EAX=12345678h on a 386. Give AX, AH and AL. Then independently replace AH with ABh.

Show worked answer

AX=5678h, AH=56h, AL=78h. Replacing AH gives EAX=1234AB78h: the other bits remain.

03 · Decode a selector

Decode selector 005Fh and give the descriptor byte offset within its table.

Show worked answer

Index=11, TI=1 (current LDT), RPL=3. Entry byte offset=11×8=58h, not 5Fh.

04 · Check a descriptor-table boundary

The selected entry has index 11. Does a table limit of 005Eh include the complete descriptor?

Show worked answer

No. The descriptor spans offsets 58h–5Fh. The final byte 5Fh exceeds table limit 5Eh.

05 · Do not multiply the selector

Selector 0058h chooses a descriptor with base=81230h and limit=FFFFh. Find the address of a byte at offset FFECh without paging.

Show worked answer

The offset is within bounds. Address=81230h+FFECh=9121Ch. The descriptor’s base, not 0058h×16, supplies the segment start.

06 · Check the whole operand

A normal expand-up segment has limit=01FFh. Can a word read begin at 01FFh?

Show worked answer

No. The word also needs offset 0200h. A byte read there is allowed; a two-byte read crosses the segment bound.

07 · Scale the limit

An 80386 descriptor has raw limit=00001h and G=1. Find its effective limit and size.

Show worked answer

Effective limit=1×4096+4095=1FFFh. Size=2000h=8192 bytes. The limit names the final byte, not the start of the last page.

08 · Distinguish a naming estimate from RAM

Does 2×8192×4 GiB prove that a 386 has a flat 64-TiB physical address space?

Show worked answer

No. It is an idealized aggregate of segment-relative ranges; descriptors can overlap and some entries are unavailable. The ordinary 386 linear address space is 4 GiB.

09 · Select the default segment

BP=110Ch, SI=1002h, SS=2000h. Find the physical address for [BP+SI+30] on an 8086.

Show worked answer

30 decimal is 1Eh. Offset=110Ch+1002h+1Eh=212Ch. BP selects SS, so physical address=20000h+212Ch=2212Ch.

10 · Read a little-endian word

Bytes at DS:0006h and DS:0007h are B8h and 90h. BX=4. What does MOV AX,[BX+2] load?

Show worked answer

AX=90B8h, with AL=B8h and AH=90h. MOV AL,[BX+2] alone would preserve the old AH.

11 · Find the high pushed byte

BP retains the original SP. PUSH AX with AX=011Ah is followed by PUSH CX with CX=2F3Dh. What is [BP-3]?

Show worked answer

It is 2Fh, the high byte of CX. The new SP is BP−4, which points to the low byte 3Dh.

12 · Choose a nondestructive zero test

Why is CMP AL,AL unsuitable for checking whether the original AL was zero?

Show worked answer

It compares a value with itself and always sets ZF=1. Use TEST AL,AL or CMP AL,0 to ask whether the original value is zero.

13 · Clear a bit without damaging others

AL=ADh. Clear bit 2 and give the result.

Show worked answer

Use AND AL,0FBh. ADh AND FBh=A9h. A TEST would leave ADh unchanged.

14 · Trace a changing shift count

AX=00FFh and CX=2. A loop body is SHL AX,CL followed by LOOP back. What is AX at termination?

Show worked answer

The first shift count is 2: AX=03FCh. LOOP leaves CX=1. The next shift count is 1: AX=07F8h. LOOP then reaches zero.

15 · Separate unsigned carry from overflow

For byte D4h−5Dh, give the result, CF and OF.

Show worked answer

Result=77h. CF=0 because unsigned 212≥93. OF=1 because signed −44−93=−137 is below −128.

16 · Interpret the literal before summing

A loop adds integers 1 through 12h, inclusive. Is its sum 78 or 171 decimal?

Show worked answer

12h is 18 decimal, so the sum is 18×19/2=171=ABh. A loop ending at decimal 12 would have sum 78 instead.

17 · Compare floating-point fields

Order binary32 words BF800000h,44800000h and 46800000h by represented numerical value.

Show worked answer

They represent −1,1024 and 16384. The negative value comes first; the two positive normal numbers have unbiased exponents 10 and 14.

18 · Handle a special exponent

What do binary32 words 00000001h and 7F800000h represent?

Show worked answer

00000001h is the smallest positive subnormal value, 2⁻¹⁴⁹. 7F800000h is positive infinity. Neither uses the ordinary normal-number implicit-leading-1 rule.

7. Which ordinary 8086 operand defaults to SS?

Answer key for offline revision and printing

1. B. The 80286 keeps 16-bit FLAGS; EFLAGS belongs to the 80386 model.

2. A. The selected descriptor supplies the base, bounds and attributes.

3. C. 0058h shifted right three bits is 000Bh, or 11 decimal.

4. B. Offsets 0 through FFh are inclusive, giving 256 bytes.

Corrections and boundaries

  • 80286 FLAGS is 16-bit; EFLAGS is introduced by the 80386. Visible segment selectors remain 16-bit in the later models described here.
  • A selector chooses a descriptor. It does not directly name a physical segment base, and table membership alone does not grant access.
  • For expand-up segments, the effective limit is inclusive. Granularity affects that limit; paging can translate the resulting linear address further.
  • The textbook 1-GiB / 64-TiB multiplications are idealized segmented naming estimates, not flat physical-memory capacities.
  • LOOP decrements CX, not CL alone, and preserves FLAGS. A body that overwrites CL also overwrites part of CX.
  • Some revision questions are incomplete in the captions. Complete examples here teach the reasoning without inventing missing original choices or claiming an exact unseen answer key.
